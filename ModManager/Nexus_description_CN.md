# ER2 Mod Manager v1.7.9

> **v1.7.9：** 延迟建页转正：默认开启（`Ui / lazyBuild`）。此前压着默认，是因为"展开时插行"三次造成"点开 mod 没内容"；如今真因已定案并修复（插入点被自己的兜底钳掉）、每次延迟构建都会自检、异常自动回退整页常规建页、展开窗口探针四个采样点全部干净，且经多轮实测确认。进 MODS 页的建页成本从 970 行 / 0.3~0.6 秒降到 71 行 / 35~100ms。想要旧行为关掉开关即可——常规建页路径一字未动。

> **v1.7.8：** 热键冲突块加了块头：计数 + 隐藏/显示按钮。块头始终显示（"⚠ 热键冲突 N 组"），就算收起了明细也能看到有几组；按钮**原地**收起/展开明细行（不整页重建），并把选择写进 `Ui / hotkeyWarnings` 且**立即落盘**（重启后保持）——同一项也会出现在 ER2 Mod Manager 自己的设置列表里，两处入口天然同步。同时修掉"多个冲突看着只有一个"的真因：明细行的行高按 **500px** 行宽估算，而标签实际可用只有 ~400px（行宽 425 − 标签左右边距），较长的警告被少算行数、文字溢出行底叠进下一条警告，好几条冲突在视觉上糊成一条；现在可用宽度从内容页实测（取不到时退保守值），每条警告都能拿到自己需要的行数，加上 1.7.7 的"一键一行聚合"，重复配对也没有了。

> **v1.7.7：** 按键冲突提示按"本机实际装着的全部 cfg"做了一次审计，查出并修掉两个缺陷。其一，冲突扫描比渲染端更宽松：键名碰巧含 "key" 的 **String** 条目都会被当成热键参与比对——本机的实锤案例是 More Physics 的 `ExcludedNameKeywords`（逗号分隔的预制体名单），它一直参与扫描，若两个 mod 的名单默认值恰好相同就会弹出一条假"热键冲突"；现在 String 条目还必须"值像按键"（F5 / Space / Mouse0 这类单词、A+B 组合或空值），名单、路径、句子一律排除。其二，三个绑定同用一键时旧实现报两行（"A 与 B""A 与 C"），B 与 C 的关系反而看不到；现在**一键一行聚合列出全部绑定**，同一 mod 内部的自冲突也会列出来。打开 `Debug / debugLog` 时扫描会报告找到几组冲突。参考：本机当前有三组**真实**冲突（页面上都有列出）：F（Advanced Combat Movement "Follow Or Marker" × ER2 Battlefield Commander "Key Scatter"）、F9（ACM "Restart Mission" × Battlefield Commander 的上帝模式键）、G（Battlefield Commander "Key Pack" × ER2 Universal Generation 的面板键）。

> **v1.7.6：** 淡入现在也覆盖翻页、设置分组与单个选项，不再只有展开 mod。整页（进入 MODS 页、离开再回来、自愈重建）通过**页容器上的一个 CanvasGroup** 整块淡入；设置分组、以及单项的"简介行/还原行"与展开 mod 用的是同一套手感，时长统一由 `Ui / revealMs` 决定。翻页闪烁同时做了硬化：每帧清理"游戏异步填充协程灌进我们页面的原生行"时原先直接 `Destroy`——而销毁要到**帧末**才生效，那一帧它们仍会被画出来，这正是"翻页闪一下"的样子；现在改为**先 SetActive(false)**（立即生效）**再 Destroy**。翻页路径还会重新确认命中区颜色（行被停用再启用时会退回不透明白的那个 1.5.13 老毛病，而建页正好是一次上百行的批量启用），发现异常当场纠正并按故障级告警。整页淡入不会反复重放：自愈重建可能连着触发，但整页淡入只做一次（否则会变成"页面反复淡出"，比闪烁更糟）；单次超过 300 行的建页跳过淡入、只静默一帧——动画永远不会变成更贵的那个选项。打开 `Debug / debugLog` 后，每次建页都会像展开那样被探针采样（同帧 / +0.03s / +0.13s / +0.36s），给出页面的行位置是否落定、命中区颜色的最坏值、内容高度、页面里"非本 mod 的子物体"个数，以及**帧号**；翻页与建页日志也都带上了帧号——"建页比按键晚了一帧"这类问题可以直接看出来，不用推断。（1.7.5 的日志已验证展开路径：四个采样点都没有未落定的行、没有不透明命中区、内容高度恒定——这也正是剩下的翻页闪烁得以凸显的原因。）

> **v1.7.5：** 展开 mod 不再闪。在延迟建页下，展开一个折叠的 mod 会现建它整段设置行；行本身当帧就排好了，但有几处外观细节要到下一拍才落定，于是可能有一两帧画成"半成品"——就是你看到的"选项都会闪一下"。现在**新建的行改为淡入**（`Ui / revealMs`，默认 200 毫秒），不再"啪"地出现：版面立刻让开、内容随后跟上，展开从"闪一下"变成一段过渡；CanvasGroup **不参与布局**，所以行照样占位，下面的行不会因此多跳一次。另外，每次展开都会**重新确认行的命中区颜色**——行被停用时它的渲染色会被清掉，再启用时靠选中态过渡重新写上，这条链只要漏掉一拍，命中区就会恢复成**不透明白**（与 1.5.13 修掉的白块同源）；发现异常当场纠正，并按故障级（不受 `debugLog` 门控）写进日志。淡入可用 `Ui / revealAnim` 关掉；单次展开超过 300 行时会跳过淡入——超大 mod 宁可瞬时显示，也不能让"掩饰"本身变成卡顿源。打开 `Debug / debugLog` 时，每次展开还会在四个时间点（同帧 / +0.03s / +0.13s / +0.36s）各打一条 `[MM-flash]`，给出行的位置是否已落定、命中区颜色的最坏值、以及内容高度——正好对应闪烁的三类物理成因，下次报告可以直接说结论而不是靠猜。

> **v1.7.4：** 修复延迟建页把设置插到列表末尾而非标题下方（即"点了打不开"）。插入点算对了，却过了一道"安全兜底"——"目标位置在新建行之前就用新建行的位置"，而新建行总是追加在末尾、标题必然在它们之前，于是兜底每次都命中。该兜底已删除、位置直接采信；保留的结构自检正是在实测中抓到它（报"row[0] 位置不连续"并退回常规建页——这就是稍后再点就开的原因）。此缺陷只可能出现在延迟路径；常规建页时兜底是空操作，故开关关闭时一直正常。

> **v1.7.3：** 设置页在 `Ui / lazyBuild` 下可以明显更快地打开，且该选项现在**失败可自愈**。建页会预先建好每个 mod 的每一项设置（970 行，实测 0.34~0.59 秒）——就是进设置页的那一下顿；打开该选项后折叠的 mod 只留标题行、首次展开才建其设置。此方案此前三次因"点开 mod 看不到内容"被撤回，那些原因现已查清；而且**页面现在会对延迟构建自检**（新行是否紧跟标题、页面高度是否跟上），失败先重试，连续两次失败即本会话弃用延迟路径并整页重建，同时记录原因——最坏只是一次常规建页。实机确认前仍默认关闭。建页日志亦新增分阶段耗时。

> **v1.7.2：** 收藏的 mod 现在点一下即展开——收藏区条目原先只置了"展开"状态却没真展开，于是点标题的第一下只是取消那个看不见的状态（故有"要点两下"之感），现在两条路径共用同一个函数；鼠标经过收藏条目会**文字变亮**（原先只有 3.5% 白的行底色，深色底上等于看不见）；★ / 还原默认 / 重置全部 / 复制全部这些按钮恢复了悬停与按下反馈（自 1.3.1 起被关闭）；收藏的 mod 星标改为金色，不再与未收藏同色。

> **v1.7.1：** 修复收藏区"占着版面却看不见"——标签矩形纵向锚点固定在中间、两端偏移写 0，导致高度为 0，而没有高度的文字一个字都画不出来（行一直是激活并参与布局的，所以只是把页面往下推了一条空白）。这些标签改用与 mod 元信息行一致的定高写法（"默认值 …"标签的同一缺陷也一并修了）。另外：**mod 一律折叠启动**——"哪些 mod 是展开的"不再跨启动保存（而"mod 内打开过哪些分区"仍然记住）。

> **v1.7.0：** 新增**收藏 mod**——每个 mod 标题行右侧有 ★，点击即出现在顶部收藏区，点条目会展开该 mod 并直接滚到它（跨重启保存，最多 24 个）。同时**移除 1.6.x 的搜索框**：用关键词过滤这个列表对页面形态的扰动远大于帮助（一次按键可能让数百行重排）；收藏覆盖同一需求且不让任何东西移位。

> **v1.5.25：**> **v1.5.25：** 设置分组恢复**默认收起**（回到一直以来的样子）。1.5.23 为排查"点开 mod 没内容"曾改成默认展开，但真因是展开记忆在 1.5.20 被关掉——记忆现已恢复，你展开过的分组会跨会话记住。记忆正常后，原默认值（收起）不会再让 mod 看起来是空的。

> **v1.5.24：** 实验性的"延迟建页"改为**默认关闭、暂不推荐**。它把打开 MODS 页的成本从 942 行/约 300ms 降到 46 行/约 60ms，但"在展开时插入行"这个做法已三次造成"点开 mod 看不到内容"（1.5.9、1.5.19、1.5.23）。本次修掉一个明确缺陷——插入锚点原先记为"容器当前的最后一个子物体"，引用失效后新行被追加到列表最末尾而非标题下方，内容存在却落在可见区下方很远；现在改用标题自身的父级对象。开关仍保持关闭直到在游戏内确认；打开页面恢复约 0.3 秒，展开回到稳定的"原地显隐"。

> **v1.5.23：** mod 内的设置分组现在**默认展开**，且"记住展开状态"恢复默认开启。这是同一个问题的两面：含多个分组的 mod 以前展开只显示分组标题（4~7 行灰色小字，真正的设置折在下一层），看起来像"没有内容"；而 1.5.20 关掉了保存这份状态的记忆（当时的推断是"只在重启后才有意义"），那是误判——它同时也是这份状态的唯一保存途径。现在展开 mod 直接看到设置；分组仍可收起，你主动收起过的会保持收起。

> **v1.5.21：** 两处修复。偶发闪烁来自行内缩——原生视口在"预留滚动条空间"与"不预留"之间切换（目标值 24 ↔ 8 反复跳），每次翻转都写入新尺寸并**同帧强制重排整列**。行宽其实几乎不变（426 ↔ 425），所以强制重排现在只保留给首次应用，之后的翻转仅标记待重排。另一处是延迟建页下"点开 mod 没有内容"：原重建只覆盖行容器，而容器本身是内容页的子物体——新行虽然存在、已激活、内容高度也增长了，却落在可见范围之外。现在重建两层、刷新画布，并在下一帧补排一次。

> **v1.5.20：** 展开状态记忆改为**默认关闭**。会话内它本来就不会丢（状态在内存里，翻页与重开设置都保留），落盘只对重启之后有意义、收益很小；而它会抵消延迟建页——被记住展开的 mod 进页时就必须把设置建出来。功能与开关（`Ui / rememberExpanded`）都保留，只是不再默认参与。

> **v1.5.19：** 新增可选的延迟建页（`Ui / lazyBuild`，**默认关闭**）。打开 MODS 页会预先建好每一项设置——实测 28 个 mod 共 942 行、0.3~0.4 秒，这正是进设置页时的那一顿；打开开关后折叠的 mod 只留标题行、首次展开才建设置。默认关闭是因为早先（1.5.9）的同方案出现过"点开没反应"且始终未能解释；现在开关打开时会把定位所需的全部状态打进日志。

> **v1.5.18：** 修复 mod 元信息行的排版。它此前复用"配置项说明"的绘制函数，而那个函数按字符数估高——于是这行比应有的高一倍，并把列表整体下推。现在它是定高的单行、字号更小、按实测宽度截断，且不再重复标题已显示的 mod 名。

> **v1.5.17：** 四项体验改进。**标签不再糟蹋缩写**——AI 被显示成 "Ai"、HUD 成 "Hud"、UI 成 "Ui"、MG42 成 "Mg 42"；现在按已知缩写白名单保持大写，并把缩写与紧随的数字合并（MG42、M1），而 SCREAMING_SNAKE_CASE 键仍显示为 "Max Count" 而非 "MAX COUNT"。**尊重第三方 ConfigurationManager 属性**——被标为 `Browsable = false` 的条目（mod 的内部/调试项）不再列出、声明的 `Order` 按序排列，均反射读取、无安装依赖。**每个 mod 会自报身份**——全名、GUID、版本与条目数一行显示，"复制全部"也带这一行。**展开状态跨重启记忆**——上次展开的 mod 与分区下次启动自动恢复（`Ui / rememberExpanded` 可关）。

> **v1.5.16：** 翻页点击音效恢复——原因是**时机**而非调用失败。1.5.15 把播音挪到页面动作之后仍然无声，而原生页面之间翻页正常有声；音效探针也从未报过一次失败，说明调用成功、声音被"吞掉"了。整页重建会在一帧内重建上千个 UI 对象，打进这一帧的声音出不来。现在翻页音效改为**排队延迟播放**：入队后 0.25 秒由每帧轮询补播，等重建尘埃落定后再响。

> **v1.5.15：** 第二次尝试修无声翻页：原来在页面动作之前播音，紧随其后的重建把刚开始播放的声音对象一起销毁了。现在改为页面动作之后播放——进入时在 MODS 页重建之后，离开或绕回首页时在切页之后。

> **v1.5.14：** 仅诊断。翻页音效无声，但所有分支都调用了 ClickSound，唯一能藏住失败的地方就是调用外层的空 catch。现在失败必留痕，从而排除了"异常"这一可能，让随后两版把方向锁定在播放时机。

> **v1.5.13：** **白闪被抓到了，而且有录像为证。** 对一段屏幕录制做逐帧亮度分析（每帧平均亮度）后跳变清晰可见：125 -> 344 -> 97，持续两帧（约 67 毫秒），正好发生在 MODS 页出现的那一刻。亮帧里每一行都被一块整行宽的白色矩形覆盖——那是每行携带的透明点击区（一个白色 Image，其可见性由 Button 的颜色块控制）。成因：设置 Button 的 ColorBlock **只是存储配置、并不会立刻绘制**；Button 组件被添加的那一刻，OnEnable 用**默认**颜色块绘制渲染器（normal = 不透明白色），我们的透明 normal 要等第一次状态变化才生效——于是所有点击区在头两帧显示为纯白。现在配好颜色块后立即把 normal 色画到渲染器上，点击区从被创建的那一帧起就是透明的。

> **v1.5.12：** 回退 1.5.9 的"延迟构建"。游戏日志证明展开回调确实执行、行也确实存在，但内容就是看不见——而这一现象正是从 1.5.9 开始，所以这个高风险折中撤销，建页恢复为一次建好。1.5.11 的滚动位置还原以同样理由移除（未验证的猜测，且本身可能移动视口）。两者换成一个决定性诊断：每次展开后记录有多少行激活、多少落在视口内、行在屏幕上的位置与滚动位置——无论还剩什么问题，下一条日志都能指出是哪一种。

> **v1.5.11：** 闪动有了具体机制：展开/折叠会改变可滚动内容的高度，而滚动位置按比例存储——高度一变，同一比例就指向别处，整列瞬间跳一下。这就是那记闪动，也解释了它为何与"点击设置后的闪动"看起来完全一样。现在记住你正在看的**像素**位置并在高度变化后还原。同时每次展开/折叠加一条日志，这是区分"点了没反应"两种可能的唯一办法。

> **v1.5.10：** 修复上一版的回归（点击一个 mod 却展开另一个）：延迟构建记住的行下标在别的 mod 展开后被整体挤位。现在插入点在使用那一刻现查。第二轮修闪动：行宽原来与容器当前尺寸比较，而该尺寸由父级布局每帧重算，于是每帧重写并整列重排；现在与上次打算写入的目标值比较。

> **v1.5.9：** 两个修复都来自游戏日志而非猜测。闪动的选项：每次点击把高度推给了行容器而不是设置页的 content 对象，容器带 Content Size Fitter，高度下一帧被重算掉并来回跳（实测 1644 <-> 1784 像素），每次跳变整列重排。现在高度落在真正的 content 对象上，稳定下来。翻页无响应：打开页面会重建每个 mod 的每一项设置（约上千对象/次翻页），现在折叠的 mod 只保留标题行，首次展开时才构建。

> **v1.5.8：** 找到了点击白闪，而且根本不在列表里。在 MODS 页按左箭头时翻页被交还给游戏自己的页签处理逻辑，而我们持有的页号（4）对只认识第 0~3 页的游戏来说越界——游戏按不认识的索引重填了整个设置面板，一次整屏重绘就是那记白闪，每次离开该页必现。现在 MODS 页自己处理左箭头并回到最后一个原生页，与"原生末页按右箭头进入 MODS"完全对称。

> **v1.5.7：** 无行为改动，仅诊断。上一版的理论（页面被重建）经游戏日志核对完全不成立——测试期间一次重建都没有发生。本版加了一个探针：在强制重排之后检测是否有行叠在同一纵向位置——那正是白闪的物理成因（浅色值框互相叠成一块白）。

一个给 Easy Red 2 的 BepInEx mod 用的游戏内设置管理器：在游戏原生设置菜单里加一个原生观感的 MODS 页，所有插件的配置都能当场修改——**零硬编码翻译表**，因此对现在和将来安装的任何 mod 都自动生效。

## Description（简介）

- 在游戏原生设置（Esc 菜单）里新增一个 **MODS** 页——每个已加载 BepInEx 插件的选项都以原生风格控件呈现：开关、下拉框、滑条与数字输入框。
- **全自动、零维护**：自动发现每个已加载插件并渲染它暴露的所有配置项。配置项标签由键名人性化生成（`enableAIVaulting` → `Enable AI Vaulting`），第三方与将来的 mod 都能直接显示可读名称，无需任何针对单个 mod 的对照表。
- **mod 按字母排序**，带字母分组标题；排序与分组会剥离 "Easy Red 2" / "ER2" 前缀（展开时仍显示完整名）。
- 没有配置项的 mod 也以只读的「已安装」条目出现，让你看到所有已加载的内容。
- 控件克隆自游戏自身的设置界面，观感与原生一致。
- **暂存式自动保存**：离开设置界面时自动保存改动。
- 支持 bool / 整数 / 浮点 / 字符串 / KeyCode——自由文本给输入框，快捷键点击按钮后按新键重绑，每一项都保证能渲染。

## Installation instructions（安装说明）

1. 为 Easy Red 2 安装 BepInEx 6（IL2CPP）。
2. 把 `ER2_ModManager.dll` 复制到 `<Easy Red 2 目录>/BepInEx/plugins/`。
3. 启动游戏，打开设置（Esc）→ MODS 页会列出每个插件的配置。

## Main features（主要特性）

- 从原生设置界面克隆的原生观感 MODS 页。
- 自动发现每个已加载的 BepInEx 插件并渲染其全部配置项——无硬编码 mod 列表。
- 字母排序 + 字母分组标题；剥离 ER2 / Easy Red 2 前缀便于查找。
- 配置项标签人性化（camelCase / snake_case → 可读文本），对任何 mod（含第三方）都适用。
- 开关 / 下拉 / 滑条 / 数字输入 / 自由文本，覆盖全部常见配置类型。
- 数字输入带取值范围提示（并有引擎字体兜底，保证数字总能显示）。
- 快捷键捕获重绑（含枚举型快捷键）。
- 改动过的值带标记，一眼看出与默认值的差异，且**任意单项都能单独还原**（旁边会显示它的默认值）。
- 整个 mod 的"重置全部"是两段式：第一次点击只是请求确认，且会自动过期。
- 作者标记为"需重启生效"的设置会被标注，保存这类改动时会提示有多少项需要重启。
- 页脚提供每个 mod 的复制与重置，并有屏幕闪烁反馈。
- 双向翻页循环（第一页 ⇄ MODS 页），保留原生点击音效。
- 暂存式自动保存；尊重每个插件自己的总开关。
- 兼容游戏 2.1.x 的设置界面重构。
- 尊重第三方 ConfigurationManager 属性：被标为隐藏（`Browsable = false`）的条目不列出，声明的 `Order` 按其排序（反射读取，无依赖）。
- 每个 mod 显示自己的身份（全名 / GUID / 版本 / 条目数），"复制全部"也带同一行。
- 记住每个 mod 内部打开过的设置分组，跨游戏重启保持（`Ui / rememberExpanded`，**默认开启**）；mod 本身一律折叠启动。
