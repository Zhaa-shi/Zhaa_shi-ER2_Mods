ER2 Mod Manager - 游戏内 mod 设置管理器
===============================================
Version 1.7.9 | Easy Red 2（BepInEx 6 / IL2CPP）

功能概述（WHAT IT DOES）
------------
在游戏原生设置菜单里新增一个「MODS」页（游戏内按 Esc → 选 MODS 页签）。所有已加载的
BepInEx 插件的配置都会以原生风格的控件呈现：开关、下拉框、滑条与数字输入框。

全自动、零维护：管理器自动发现每一个已加载的插件，并自动渲染它暴露的所有配置项。
配置项标签由键名人性化生成（enableAIVaulting -> "Enable AI Vaulting"），因此第三方
mod 与将来新增的 mod 都能直接显示可读名称，无需任何针对单个 mod 的对照表。

没有配置项的 mod 也会以只读的「已安装」条目出现，让你看到所有已加载的内容。

改动会先暂存，离开设置界面时自动保存（没有会丢失的保存按钮）。

安装（INSTALLATION）
------------
1. 为 Easy Red 2 安装 BepInEx 6（IL2CPP）。
2. 把 ER2_ModManager.dll 复制到 <Easy Red 2 目录>/BepInEx/plugins/。
3. 启动游戏，打开设置（Esc）→ MODS 页会列出每个 mod 的配置项。

功能（FEATURES）
--------
- 控件克隆自游戏自身的设置界面，观感与原生一致。
- 自动发现每个已加载的 BepInEx 插件并渲染其全部配置项——无硬编码 mod 列表、无翻译表。
- mod 按字母排序，并有字母分组标题（"A"…"Z" / "0-9" / "#"）便于查找。
- 列表会剥离 "Easy Red 2" / "ER2" 前缀（排序与分组用短名）；展开某个 mod 时仍显示完整名。
- 配置项标签人性化（camelCase / snake_case -> 可读文本），对任何 mod 都适用。
- 没有配置项的 mod 以只读「已安装」条目出现。
- 支持 bool / 整数 / 浮点 / 字符串 / KeyCode 五类配置项。自由文本（颜色、地址……）给文本
  输入框；枚举型快捷键给"点击后按键重绑"按钮。每一项都保证能渲染（最差也有一行只读兜底）。
- 数字输入带取值范围提示；没有可用模板时回退为滑条。
- 快捷键可点击按钮后按新键完成重绑（带捕获）。
- 每个配置项都支持复制 / 重置，并有屏幕上的闪烁反馈。
- 翻页循环：第一页按左箭头直接跳到 MODS 页，MODS 页按右箭头回到第一页。保留原生点击音效。
- 暂存改动自动保存；尊重每个插件自己的总开关。
- 兼容游戏 2.1.x 的设置界面重构（异步填充流程已处理）。
- 用 mod 标题行上的 ★ 收藏该 mod；收藏区在页面顶部，点击即展开并跳到该 mod。
- 与向原生设置菜单添加自有页面的第三方 mod（如 Advanced Combat Movement）共存，两边页签
  都保持可达。
- 尊重第三方 ConfigurationManager 属性：被标为隐藏（`Browsable = false`）的配置项不列出，声明的 `Order` 按其排序（反射读取，无编译期依赖）。
- 每个 mod 显示自己的身份（全名 / GUID / 版本 / 条目数），"复制全部"也带同一行——报问题时一眼定位版本。
- 记住每个 mod 内部打开过的设置分组，跨游戏重启保持（`Ui / rememberExpanded`，**默认开启**）；mod 本身一律折叠启动。

更新日志（Changelog）
----------------
1.7.9
- **延迟建页转正：默认开启**（`Ui / lazyBuild`）。此前压着默认，是因为"展开时插行"三次造成"点开
  mod 没内容"；如今真因已定案并修复（插入点被自己的兜底钳掉）、每次延迟构建都会自检、异常自动回退
  整页常规建页、展开窗口探针四个采样点全部干净，且经多轮实测确认。进 MODS 页的建页成本从
  970 行 / 0.3~0.6 秒降到 71 行 / 35~100ms。想要旧行为关掉开关即可——常规建页路径一字未动。

1.7.8
- **热键冲突块加了块头：计数 + 隐藏/显示按钮。** 块头始终显示（"⚠ 热键冲突 N 组"），就算收起了明细
  也能看到有几组；按钮**原地**收起/展开明细行（不整页重建），并把选择写进 `Ui / hotkeyWarnings` 且
  **立即落盘**（重启后保持）。同一项也会出现在 ER2 Mod Manager 自己的设置列表里，两处入口天然同步。
- **修掉"多个冲突看着只有一个"的真因。** 明细行的行高按 **500px** 行宽估算，而标签实际可用只有
  ~400px（行宽 425 − 标签左右边距）——较长的警告被少算行数，文字溢出行底、叠进下一条警告，
  好几条冲突在视觉上糊成一条。现在可用宽度从内容页实测（取不到时退保守值），每条警告都能拿到
  自己需要的行数；加上 1.7.7 的"一键一行聚合"，重复配对也没有了。

1.7.7
- **按键冲突提示按"本机实际装着的全部 cfg"做了一次审计**，查出并修掉两个缺陷。其一，冲突扫描比渲染端
  更宽松：键名碰巧含 "key" 的 **String** 条目都会被当成热键参与比对。本机的实锤案例是 More Physics 的
  `ExcludedNameKeywords`（逗号分隔的预制体名单）——它一直参与扫描，若两个 mod 的名单默认值恰好相同就会
  弹出一条假"热键冲突"。现在 String 条目还必须"值像按键"（F5 / Space / Mouse0 这类单词、A+B 组合或空值），
  名单、路径、句子一律排除。其二，三个绑定同用一键时旧实现报两行（"A 与 B""A 与 C"），B 与 C 的关系反而
  看不到；现在**一键一行聚合列出全部绑定**，同一 mod 内部的自冲突也会列出来。
- 打开 `Debug / debugLog` 时，扫描会报告找到几组冲突（`hotkey conflict scan: N`）。
- 参考：本机当前有三组**真实**冲突（页面上都有列出）：**F**（Advanced Combat Movement "Follow Or Marker"
  × ER2 Battlefield Commander "Key Scatter"）、**F9**（ACM "Restart Mission" × Battlefield Commander
  的上帝模式键）、**G**（Battlefield Commander "Key Pack" × ER2 Universal Generation 的面板键）。

1.7.6
- **淡入现在也覆盖翻页、设置分组与单个选项**，不再只有展开 mod。整页（进入 MODS 页、离开再回来、自愈重建）
  通过**页容器上的一个 CanvasGroup** 整块淡入；设置分组、以及单项的"简介行/还原行"与展开 mod 用的是同
  一套手感，时长统一由 `Ui / revealMs` 决定。
- **翻页闪烁的硬化。** 每帧清理"游戏异步填充协程灌进我们页面的原生行"时原先直接用 `Destroy`——而销毁要
  到**帧末**才生效，那一帧它们仍会被画出来，这正是"翻页闪一下"的样子。现在改为**先 SetActive(false)**
  （立即生效）**再 Destroy**。同时，翻页路径也**重新确认命中区颜色**（行被停用再启用时会退回不透明白的
  那个 1.5.13 老毛病，而建页正好是一次上百行的批量启用）：发现异常当场纠正，并按故障级写进日志。
- **整页淡入不会反复重放**：自愈重建可能连着触发，但整页淡入只做一次（否则会变成"页面反复淡出"，比闪烁
  更糟）；单次超过 300 行的建页跳过淡入、只静默一帧——动画永远不会变成更贵的那个选项。
- 诊断：打开 `Debug / debugLog` 后，**每次建页都会像展开那样被探针采样**（同帧 / +0.03s / +0.13s / +0.36s），
  给出页面的行位置是否落定、命中区颜色的最坏值、内容高度、页面里"非本 mod 的子物体"个数，以及**帧号**。
  翻页与建页日志也都带上了帧号——"建页比按键晚了一帧"这类问题可以直接看出来，不用推断。
- 1.7.5 的日志已验证：展开 mod 时四个采样点都**没有**未落定的行、**没有**不透明命中区、内容高度恒定——
  展开路径是干净的，这也正是剩下的翻页闪烁得以凸显的原因。

1.7.5
- **展开 mod 不再闪。** 在延迟建页下，展开一个折叠的 mod 会现建它整段设置行。行本身当帧就排好了，但有
  几处外观细节要到下一拍才落定，于是可能有一两帧画成"半成品"——就是你看到的"选项都会闪一下"。现在
  **新建的行改为淡入**（`Ui / revealMs`，默认 200 毫秒），不再"啪"地出现：版面立刻让开、内容随后跟上，
  展开从"闪一下"变成一段过渡。CanvasGroup **不参与布局**，所以行照样占位，下面的行不会因此多跳一次。
- **每次展开都会重新确认行的命中区颜色。** 行被停用时它的渲染色会被清掉，再启用时靠选中态过渡重新写上；
  这条链只要漏掉一拍，命中区就会恢复成**不透明白**——与 1.5.13 修掉的白块同源。发现异常会**当场纠正**，
  并按故障级（不受 `debugLog` 门控）写进日志。
- `Ui / revealAnim`（默认开）可关掉淡入，改回瞬时显示；单次展开超过 300 行时会跳过淡入——超大 mod 宁可
  瞬时显示，也不能让"掩饰"本身变成卡顿源。
- 诊断：`Debug / debugLog` 打开时，每次展开会在四个时间点（同帧 / +0.03s / +0.13s / +0.36s）各打一条
  `[MM-flash]`，给出行的位置是否已落定、命中区颜色的最坏值、以及内容高度——正好对应闪烁的三类物理成因，
  下次报告可以直接说结论而不是靠猜。

1.7.4
- **修复：延迟建页把某个 mod 的设置插到了列表末尾，而不是它的标题下方**——这就是"点了打不开"的原因。
  插入点本身算对了（标题行的下一行），但随后过了一道"安全兜底"：**"若目标位置在新建行之前，就用新建行的
  位置"**。而新建的行总是追加在列表末尾，标题行的位置必然在它们之前 → 兜底**每次都命中**，把行又推回末尾。
  该兜底已删除，位置直接采信；唯一保留的保护是结构自检——而它在实测中正好抓到了这个问题（报
  `row[0] 位置不连续` 并退回常规建页，这就是"过了一会再点就开了"）。另外，这个缺陷只可能出现在延迟路径上：
  常规建页时行本来就是在标题之后紧接着建的，兜底在那里是空操作，所以这个开关关着的时候一直正常。

1.7.3
- **打开设置页的成本大幅下降——`Ui / lazyBuild` 现在带失败自愈。** 建页会把每个 mod 的每一项设置都预先建好：
  970 行，本机实测 0.34~0.59 秒，这就是进设置页时那一下顿。打开 `lazyBuild` 后，折叠的 mod 只保留标题行，
  其设置在你第一次展开它时才建。这个方案此前试过三次、三次都因"点开 mod 看不到内容"被撤回——那些原因现已
  查清并修好，更重要的是**现在页面会自检**：延迟构建之后会核对"新行是否真的紧跟在标题下方""页面高度是否
  跟上了内容需求"，失败先重试，连续两次失败就**本会话弃用延迟路径并整页重建**，同时把失败原因写进日志。
  于是最坏情况只是"付一次常规建页的代价"（也就是你现在本来就要付的那一下），而不会把页面弄坏。
  在实机确认之前，它仍**默认关闭**。
- 建页日志现在会报出时间花在哪（`bodies=..ms fav=..ms warn=..ms other=..ms`）——以后再报"设置页顿一下"，
  可以直接用数据回答，不必猜。

1.7.2
- **收藏的 mod 现在点一下就展开。** 点击收藏区条目原先只把该 mod 的状态置为"展开"、却没真正展开（正文行仍
  隐藏），列表看着没动；此后点它的标题，第一下只是把这个看不见的状态取消，再点一下才看得见内容——玩家
  体感就是"要点两下"。现在两条路径合用一个函数（置状态 + 显隐行 + 翻箭头 + 重排），点一下即开。
- **鼠标放到收藏条目上有反应了。** 原先唯一的反馈是行底色 3.5% 的白色高亮，在深色底上基本看不见；现在
  指针经过时该条目**文字变亮**（与 ★ 小按钮同一套机制）。
- **小按钮也有悬停反馈。** ★、还原默认、重置全部、复制全部这些按钮此前关闭了悬停/按下过渡（可追溯到
  1.3.1 的规避措施），鼠标划过毫无变化；现在悬停变亮、按下变暗。
- **收藏的 mod 星标是金色的。** 原先 ★ 与 ☆ 同为暗灰，列表里看不出哪些已收藏。

1.7.1
- **修复：收藏区看不见。** 它在页面顶部占着高度，却什么都不显示——标题没有、收藏的 mod 也没有。原因是标签
  矩形：它们用的是"纵向锚点固定在中间、两端偏移都写 0"的写法，这让矩形高度恒为 0，而没有高度的文字一个
  字都画不出来。这些行一直是激活且参与布局的，所以页面只是被一条空白往下推。现在这些标签改用与 mod
  元信息行一致的定高写法。同一缺陷也存在于"已改动设置"那一行的"默认值 …"标签上，一并修了。
- **mod 一律折叠启动。** 以前"哪些 mod 是展开的"也在保存之列，于是上个会话展开过的 mod 会在下次启动时
  带着展开状态打开，把它下面的内容全推下去。现在不再保存、也不再恢复。而 **分区**（mod 内部的设置分组）
  仍会记住你打开过的——这部分保留，否则每个 mod 里的分组都得重新点开。

1.7.0
- **新增：收藏 mod。** 每个 mod 的标题行右侧多了一颗 ★。点一下即加入页面顶部的 **★ 收藏的 mod** 区；
  点收藏区里的条目会**展开该 mod 并直接滚到它**。收藏保存在
  `BepInEx/config/er2.modmanager.favorites.txt`，重开游戏仍在（最多 24 个）。再点一次 ★ 取消。
- 移除了 1.6.x 里短暂出现过的搜索框。试用下来，用关键词过滤这个列表并不合适——它对页面形态的扰动远大于
  帮助（一次按键就可能让几百行同时重排）。**收藏覆盖了同一个需求，且不让任何东西移位**：你真正常用的那几个
  mod 就在顶部一步之遥。

1.5.25
- **设置分组恢复"默认收起"（回到一直以来的样子）。** 1.5.23 为排查"点开 mod 没内容"曾把它改成默认
  展开，但那个现象的真因是展开记忆在 1.5.20 被关掉了——记忆现已恢复，你展开过的分组会被跨会话记住。
  记忆正常之后，原来的默认值（收起）不会再让一个 mod 看起来是空的。
  实际效果：展开 mod 会列出它的分组，你点开过的分组下次仍是打开的。

1.5.24
- **实验性的"延迟建页"改为默认关闭，并标记为暂不推荐。** 它通过"折叠的 mod 到展开时才建设置"把打开
  MODS 页的成本大幅降低（46 行 / 约 60ms，原来 942 行 / 约 300ms），但"在展开那一刻插入行"这个做法
  已经三次造成"点开 mod 看不到内容"（1.5.9、1.5.19、1.5.23）。
  本次修掉了其中一个明确缺陷：记录"该插到哪一行之后"时用的是"容器当前的最后一个子物体"，这个引用一旦
  失效，新行就会被追加到列表最末尾而不是标题下方——内容确实存在，只是落在你正在看的位置下方很远。
  现在改用标题自身的父级对象，不会再漂移。尽管如此，它仍然默认关闭，直到在运行中的游戏里确认过为止。
  实际影响：打开 MODS 页恢复为约 0.3 秒（原本就是如此），展开行为回到一直稳定的"原地显隐"。

1.5.23
- **mod 内的设置分组现在默认展开，且"记住展开状态"恢复默认开启。** 这是同一个问题的两面。含多个设置
  分组的 mod，以前展开后只显示分组标题——4~7 行灰色小字，真正的设置全部折在下一层——于是点开一个 mod
  看起来"没有内容"。另外 1.5.20 依据"这点记忆只在重启后才有意义"的推断把它默认关掉了，而那是个误判：
  它同时也是这份状态的唯一保存途径，关掉后每次启动都从零开始。现已恢复开启。
  净效果：展开 mod 直接看到它的设置。分组标题仍在、也仍可收起（喜欢紧凑视图的话），你主动收起过的
  分组会保持收起。

1.5.21
- **修复偶发闪烁。** 行内缩（让行不被滚动条压住的那段留白）是每帧重算的，而原生视口会在"预留滚动条空间"
  与"不预留"之间来回切换，于是目标值在 24 ↔ 8 之间跳（实测）。旧代码每次跳都写入新尺寸并调用强制重排
  ——**整列行在同一帧重新排布**，那就是你看到的闪，也解释了为什么它不是必现：只在状态翻转的那一下发生。
  行宽其实几乎不变（426 ↔ 425），真正需要的只是"让布局知道宽度变了"，而那件事 Unity 在正常布局阶段
  自己会做。现在强制重排只在**建页后首次**保留（几何尚未定型时需要），之后的翻转只标记为待重排。
- **修复延迟建页下"点开 mod 没有内容"。** 原来的重建只覆盖行容器这一层，但该容器本身是内容页的子物体、
  位置与高度受外层支配——诊断确认行已创建、已激活、父链干净、内容高度也增长了，可新行就是落在可见范围
  之外。现在改为重建**两层**（容器 + 宿主）并刷新画布，隔一帧再补排一次（嵌套布局里的
  ContentSizeFitter 常常需要一帧才稳定）。

1.5.20
- **展开状态记忆改为默认关闭。** 两个理由都很具体：会话内它本来就不会丢——状态在内存里，翻页、重开设置
  都保留——所以落盘只对"重启游戏之后"有意义，收益很小；而它会**直接抵消延迟建页**：被记住展开的 mod
  必须在进页时就把设置建出来（光 `Combat Tweaks` 一项就是 70 行），那正是我们要省掉的开销。功能与开关
  （`Ui / rememberExpanded`）都保留，只是不再默认参与。

1.5.19
- **可选的延迟建页（`Ui / lazyBuild`，默认关闭）。** 打开 MODS 页会**预先建好每个 mod 的每一项设置**——
  本机实测 28 个 mod 共 942 行、耗时 0.3~0.4 秒，这就是你进设置页时感到的那一顿。打开这个开关后，折叠
  的 mod 只保留标题行，其设置在你**第一次展开**它时才建，于是进页只做很小一部分工作。
  它**默认关闭**：这个方案早先（1.5.9）上线过，出现了"点开没反应"——回调跑了、行也确实存在、无异常，
  但内容就是看不见，而那个谜一直没解开，所以在新方案被验证之前不设为默认。开关打开时 mod 会把过程打进
  日志（`[MM-lazy] ...`）：建了多少行、插在哪个位置、容器与行在层级里到底可不可见、容器高度与偏好高度。

1.5.18
- **修复 mod 元信息行的排版。** 每个 mod 标题下那一行（GUID / 版本 / 条目数）此前复用了"配置项说明"的
  绘制函数，而那个函数按字符数估高——最少预留两行、且假设列宽很窄，于是这行比应有的高了一倍，还把
  整个列表往下推。现在它是真正的单行：定高、字号更小、按**实测宽度**做省略号截断，并且不再重复标题
  已经显示的 mod 名（那部分占了它大部分长度）。

1.5.17
- **标签不再糟蹋常见缩写。** AI 被显示成 "Ai"、HUD 成 "Hud"、UI 成 "Ui"、FOV 成 "Fov"、MG42 成 "Mg 42"。
  现在用一份常见缩写白名单（AI / UI / HUD / FOV / MG / SMG / AP / HE / WW 以及 M、T、S 这类单字母……）
  保持大写，并且"缩写 + 紧随数字"会合并成一个词（MG + 42 → MG42，M + 1 → M1）。判据刻意用**白名单**
  而不是"整词全大写就保留"——配置文件里 SCREAMING_SNAKE_CASE 很常见，那个判据会把 MAX_COUNT 显示成
  "MAX COUNT"。没有此类键的 mod 不受影响。
- **尊重第三方 ConfigurationManager 属性。** 被 mod 标为 `Browsable = false` 的配置项（通常是它的
  内部/调试项）不再出现在列表里；mod 声明了 `Order` 时按其排序。两者都用反射读取，因此**不要求对方
  真的装了 ConfigurationManager**。未声明 Order 的 mod 保持自己的绑定顺序——只有至少一项确实指定了
  位置时才重排，因为绑定顺序通常是作者刻意的。
- **每个 mod 现在会自报身份。** 展开 mod 后第一行是它的全名、插件 GUID、版本与设置条目数；"复制全部"
  的头部也带这一行——截图求助或贴配置时，一眼就能看出是哪个 mod 的哪个版本，不必再翻 BepInEx 日志。
- **展开状态跨重启记忆。** 你展开过哪些 mod（以及其中哪些分区）会写在配置文件旁，下次启动自动恢复，
  不用每次重开同样那几个 mod；可在 `Ui / rememberExpanded` 关闭。

1.5.16
- **翻页点击音效恢复**——原因是**时机**，不是调用失败。1.5.15 把播音挪到页面动作之后仍然无声，
  而原生各页之间翻页正常有声；音效探针也从未报过一次失败——说明调用成功、声音被"吞掉"了。
  整页重建会在一帧内重建上千个 UI 对象，打进这一帧的声音出不来。现在翻页音效改为**排队延迟播**
  放：入队后由每帧轮询在 0.25 秒后补播，等重建尘埃落定、音频侧不再被冲击时再响。

1.5.15
- 第二次尝试修无声翻页：原来在页面动作**之前**播音，紧随其后的重建把刚开始播的声音对象一起
  销毁了。现在改为页面动作**之后**播——进入 MODS 页时在重建之后，离开或绕回首页时在切页之后。

1.5.14
- 仅诊断，无行为改动。翻页音效无声，但所有分支都调用了 ClickSound，唯一能藏住失败的地方就是
  调用外层那个空 catch。现在失败必留痕（"ModManager: ClickSound failed: ..."）。也正是这条
  日志排除了"异常"这一可能，让随后两版把方向锁定在播放时机上。

1.5.13
- **白闪被抓到了，而且有录像为证。** 对一段屏幕录制做逐帧亮度分析（每帧平均亮度）后跳变清晰
  可见：125 -> 344 -> 97，持续两帧（约 67 毫秒），正好发生在 MODS 页出现的那一刻。亮帧里每一
  行都被一块整行宽的白色矩形覆盖——那是每行携带的透明点击区（一个白色 Image，其可见性由 Button
  的颜色块控制，normal 态为不可见）。
- 成因：设置 Button 的 ColorBlock **只是存储配置、并不会立刻绘制**。Button 组件被添加的那一刻，
  它的 OnEnable 会用**默认**颜色块绘制渲染器——normal = 不透明白色。我们设置的透明 normal 要等
  **第一次状态变化**（比如鼠标划过该行）才被应用，于是页面上的所有点击区在头两帧都显示为纯白。
  这就是那记白闪，也解释了它为什么出现在哪里都长得一样：它总是伴随"行被创建或被重新显示"的时刻。
- 修法：配好颜色块后立即把 normal 色画到渲染器上，点击区从它被创建的那一帧起就是透明的。

1.5.12
- **回退了 1.5.9 引入的"延迟构建"。** 游戏日志证明展开回调确实执行、行也确实存在（"toggle mod
  'X' -> open rows=118"），但内容就是看不见——而这一现象正是从 1.5.9 开始。延迟构建用"必然正确
  的页面"换"翻页速度"，这笔交易不划算：1.5.10 起翻页本来就快了（每帧重写回路已消除），所以这个
  高风险折中撤销。建页恢复为一次建好；点击只切换可见性，与从前一致。
- 同样理由移除了 1.5.11 加的滚动位置还原：它是在问题尚未真正理解时叠加的未验证猜测，而且它本身
  可能移动视口。
- 两者换成一个决定性诊断：每次展开后记录有多少行处于激活、其中有多少落在视口内、行在屏幕上的
  位置，以及滚动位置："ModManager: state mod 'X' rows=118 active=118 onScreen=118 rowY=...
  viewportY=... vnp=.. contentH=.."。无论还剩什么问题，下一条日志都能直接指出是三种里的哪一种：
  行没激活、行在视口外、或行可见却没画出来。

1.5.11
- 闪动有了具体机制：展开/折叠任何东西都会改变可滚动内容的高度，而滚动位置是**按比例**存储的——
  高度一变，同一个比例就指向别处，整列内容瞬间跳一下。日志里每次点击后紧跟的正是那条
  "content height jump"。现在展开/折叠会记住视口的**像素**偏移并在之后还原，列表停在你正在看的
  位置，而不会从光标下面滑走。
- 每次展开/折叠加一条日志（mod / 分区 / 单项，以及它有多少行）。这是区分"点了没反应"两种可能
  的唯一办法：点击没到达回调，还是回调跑了但没有行可显示。
- 上一版备注：行宽已不再振荡（实测每 5 秒 0~5 次写入，而非每帧一次），且建页时 28 个 mod 只创建
  约 46 行（此前是每个 mod 的每一项都建），翻页恢复跟手。

1.5.10
- 修复上一版引入的回归：点击一个 mod 却展开了另一个。延迟构建在**建页时**记下每个 mod 标题的行
  下标，但只要上面某个 mod 被展开（会插入行），它下面所有记住的下标就整体错位，行便插进了错误的
  mod 名下。现在插入点是在插入那一刻从标题行对象现查的，不可能过期。
- 第二轮修闪动。行宽的判据原来拿**容器当前尺寸**比较，而该尺寸由父级布局每帧重算——于是判据每帧
  都报"变了"，每帧重写宽度并强制整列重排。每帧重排，看上去就是闪动。现在与**上一次打算写入的
  目标值**比较：目标不变就一个字都不写，也就不会重排。
- 诊断换了形态：行内缩日志原来只印一行、其余丢弃，恰好把最关键的信息（写了多少次）藏住了。现在
  输出每 5 秒窗口内的写入次数：个位数是健康的，几百次说明还在振荡。

1.5.9
- 选项闪动找到了可量化的原因。每次点击都把高度推给了**错误的对象**：自愈式滚动代码拿到的是行容器，
  而不是设置页自己的 content 对象。容器上挂着 Content Size Fitter，于是我们写进去的值下一帧就被
  重算掉，高度来回跳（日志实测 1644 -> 1784 -> 1644），每次跳变都把整列重新排布。这就是闪动。现在
  高度始终落在真正的 content 对象上，稳定下来而不是振荡。
- 翻页卡顿：打开页面时会**预先创建每个 mod 的每一项设置**，包含折叠起来的部分——装二十个 mod 就是
  每次翻页重建上千个对象。现在折叠的 mod 只保留标题行，其设置在**第一次展开**时才创建，之后仍然
  原地显隐；任何时候都不重建整页。
- 建页成本有日志（行数、mod 数、已建正文数、耗时毫秒），让改善可测量而不是靠推测。这条日志不受
  调试开关限制——它就是翻页问题的证据。

1.5.8
- **白闪的真因找到了，而且根本不在列表里**：在 MODS 页按左箭头时，翻页被交还给了游戏自己的页签
  处理逻辑。MODS 页是追加在原生最后一页之后的，我们持有的页号（4）对游戏来说越界——游戏只认识
  第 0~3 页。把越界页号交回去，游戏就按它不认识的索引重填了整个设置面板，一次整屏重绘，这就是
  那记白闪，而且每次离开该页必现（日志：`tab left:pass-native cur=4 myIndex=4`）。现在 MODS 页
  自己处理左箭头并回到最后一个原生页，与"原生末页按右箭头进入 MODS"完全对称。越界重绘消失。
- 同时补上上一版诊断的漏洞：重新打开设置菜单时触发的那条重建路径没有挂探针，所以"没有发生重建"
  当时只覆盖了两条重建路径中的一条。现在两条都有记录。

1.5.7
- 无行为改动，仅诊断。仍在追查点击白闪：上一版的理论（页面被重建）经游戏日志核对完全不成立——
  测试期间一次重建都没有发生，说明白闪另有来源。
- 本版加了一个探针：在每次强制重排之后检测是否有行**叠在同一纵向位置**——这正是白闪的物理成因：
  某一帧行落在同一点上，它们的浅色值框互相叠成一块白。命中时日志为
  "ModManager: rows stacked at one y after 'SelfHealScroll' - visible=.. sameY=.. containerH=.."。
- 行内缩诊断原来每帧打印，一旦打开诊断开关就会把日志灌满。现在与其他诊断一致，节流为 5 秒一条。
- 两个探针都只在 Debug / debugLog 打开时运行（默认关闭）。

1.5.6
- 继续追查剩余的点击白闪。每帧运行的自愈逻辑把**短列表**误判为**坏状态**：它只看容器高度，而
  content 高度有 200 像素的下限，于是"列表真的短"（装的 mod 少，或大部分折叠着）总会命中"布局
  从未算过"的判据，触发整页重建——而整页重建正是让整屏闪白的原因。现在改为比较**需求高度与实际
  渲染高度**，短列表被放过，只有真正没排过版的页面才重建。
- 重建也会连同原因一起记录（`ModManager: rebuilding MODS page ... reason=`），这样任何残余白闪都
  可被识别而不是靠猜；建页后也会立即把页面轮廓定稿，避免第一帧就触发该判据。

1.5.5
- 三项可靠性修复。改动过的配置项现在带标记，一眼看出哪些与默认值不同，并且**每一项都能单独还原**
  （此前只有"整体重置"）。"重置全部"现在需要第二次点击确认才会清空该 mod 的设置并保存。
  需要重启游戏才生效的设置（mod 自己的描述里写明的那些）也会被标注，并在离开菜单时统计提示——因为
  正是这类改动最像"我改了但没反应"。同时修复了长标签压到值框上的问题，并移除了最后两处残留的
  整页重建。

1.5.3
- 修好了与"向原生设置菜单添加自有页面的第三方 mod"的共存问题，首先是 Advanced Combat Movement
  （Responsive Orders）。它的页面会劫持右箭头，导致 MODS 页无法通过翻页到达；现在两个页面共用
  一条页签链，都能到达。

1.5.2
- 移除了最后遗留的开发者开关（NativeFull）以及它背后的另一套页面渲染器。它是自锁的——它是本 mod
  自己的设置项，所以显示在 MODS 页上，打开它就会让该页损坏，而关掉它又只能在同一个页面上操作。
  现在 MODS 页只有一条代码路径。

1.5.1
- 移除了遗留的开发者测试页，它可能让 MODS 页显示四行无效内容（一个空框、一个什么也不做的开关和
  滑条，以及一个写着 "click" 的框）。新增 "Debug" 开关（默认关闭），让发布版保持安静。

1.5.0
- 点击不再重建页面（因此不再白闪）；mod / 分区 / 设置项的折叠箭头常显；分区默认收起、其设置缩进
  一级；单项展开状态不再在 mod 之间串味；标签统一字号、超长用省略号而不是缩字号；值控件更小；
  mod 名称下加一条细线。本版移除了临时诊断。

1.4.0
- 极简化：去掉装饰（强调条、计数徽章、每行的箭头与每行的 重置/复制），配色收敛为两种文字色调
  加一个浅色值框，行距更紧。只保留承载信息的元素。

已知限制（Known limitations）
--------------------------------
- 本 mod 只负责"把你的改动写进各 mod 的配置文件"，不负责让改动立刻生效——需要重启的设置项会在
  离开菜单时被统计提示。
