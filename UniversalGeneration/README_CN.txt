ER2 Universal Generation v2.5.1
================================

在战场指挥官（ER2 Battlefield Commander）的 RTS 上帝视角内，按你的意愿生成任何单位、载具与物品。
作弊向小工具：无平衡惩罚，全部走游戏原生管线，生成即可用。

需求（Requirements）
--------------------------------
- Easy Red 2（BepInEx IL2CPP）
- ER2 Battlefield Commander v1.2.19 或更新（本 mod 仅在其 RTS 上帝视角内工作，宿主缺失时保持休眠）

安装（Installation instructions）
--------------------------------
1. 解压，将 ER2_UniversalGeneration.dll 放入 <游戏>/BepInEx/plugins/
2. 确认 ER2_BattlefieldCommander.dll（v1.2.8+）已安装
3. 进入战斗，按 F9 进上帝视角，按 G（或点左缘的"生成 [G]"按钮）

主要特性（Main features）
--------------------------------
- 三击出车：G → 点条目 → 点战场
- 面板零卡顿：全部目录（小队库/载具/火力点/物品）在游戏启动时后台分帧构建
- 全量条目：约 50 种基础小队 + 游戏小队库全部 400+ 战场/季节变体班（冬季、诺曼底、战争初期……）+ 游戏/DLC 全部载具与火力点（自动枚举）
- 火力点页签：游戏全部固定机枪火力点——MG34/MG42/勃朗宁/马克沁/九二式/维克斯等，地面/三脚架/碉堡三种形态，含高射机枪与 M45 四联装防空炮，默认自带机枪手
- **物品生成（2.0.0 新增，2.0.2 重写目录）**：**直接向游戏运行时物品数据库枚举**，只列出确实存在的物品——列表里出现的一定能生成，不会再"点了才发现无效"。分类由游戏自己的物品类型决定：武器 / 弹药 / 投掷物 / 装备 / 医疗食物 / 其他，每条尽量显示**游戏真实图标**。点选物品即"拿起"，拖到单位身上放进他的背包，或拖到地上丢出实物
- 阵营三选：我方 / 敌方 / 中立（平民）——生成后按阵营行为
- 我方/中立生成单位原地驻守、见敌接战、完全听 RTS 指令；**敌方生成单位走原生 AI**——自己推进进攻，与战役刷出的敌军无异（cfg 可改回驻守）
- 载具自带正式乘员且**出生即在车上**：按国别坦克组员、精确按座位数、原生 spawnOnvehicle 入座（无需等待登车；生成即可被 RTS 指挥）
- 乘员可自定义：专用坦克组员 / 任意步兵班型 / 空车
- 放置预览：**半透明幽灵模型**（真实单位剪影），左键长按拖动可旋转朝向
- 收藏：条目一键加星，跨会话保存，收藏页集中显示
- 一键清除本 mod 生成的所有单位
- 双语（EN/CN），内置中文本地化

使用说明（How to use）
--------------------------------
- G：开关生成面板（RTS 视角内）
- 面板：选阵营 → 选类别 → 点条目 → 面板收起进入放置模式
- 放置：左键确认，Shift+左键连续放置，右键/ESC/G 取消
- 物品：切到物品页签 → 点条目"拿起" → 拖到**单位身上**（绿色光环）放进背包，或拖到**地面**（琥珀光环）丢出实物。右键 / ESC / G 放弃携带
- 面板标题栏"清除"按钮：一键移除本 mod 生成的所有单位

更新日志（Changelog）

2.5.1
- **UI 自适应**：面板、放置徽标、携带徽标现在跟随**游戏自己的 UI 大小设置**（`ResourcesManager.ResolutionMult`，

  属性，倍率变化时样式自动重建。
- **定宽元素收敛进屏幕**：携带徽标原先硬编码 560px，窄屏会溢出，已修。
- **灰黑配色提亮**：2.5.0 那版偏黑，深色面互相压成一坨。现在面板→标题条→控件→行→选中
  逐级拉开 +8~14 级明度差。
- **最后的绿色清掉**：携带徽标底色（旧军绿）、拖拽目标环（原亮绿，改白）并入共享配色。

2.5.0
- **灰黑单色 UI**：面板改用共享工具层（`Shared/Er2Ui.cs`）的中性灰黑色板，不再用旧版军绿——列表行、页签、按钮、预览区统一为平整的深灰面，层次靠明度而非色相。设 `UI/uiMono=false` 可回退此前的军绿预设。
- 内部：共享工具层新增 `Mono` 开关，本 mod 与「战场指挥官」的外观由同一处控制。

2.4.2
- **无可见改动——这是为 UI 重绘打底的代码质量版本。** 面板绘制代码做了结构性重构，让 2.4.0 那类"列表画到面板外面"的问题从根上不可能复发：面板高度不再是一套需要人工与绘制代码对齐的公式。两个 mod 现在都先生成一份**行计划**（每一行一条：标题 / 阵营 / 页签 / 列表 / 分页 / 预览…），高度就是这份计划求和，绘制则遍历同一份列表。增删行再也不可能让高度与实际绘制脱节。
- **两个 mod 共用同一套 UI 工具层。** 新增共享源码 `Shared/Er2Ui.cs`，承载设计令牌（间距 / 字号 / 配色）与绘制原语（纯色填充、样式工厂、自适应页签、分页、文本自适应）。两个程序集互不引用，各自把同一份文件编译进自己。视觉改动从此改一处、两边同时生效——这是把两个 mod 重绘成统一观感的前提。
- 页签文字适配改用 `GUIStyle.CalcSize` 精确测量（原来是按字符宽度估算），并缓存结果：页签能落到准确字号，且不用每帧付测量开销。

2.4.1
- **"Mod载具"页签不再压住相邻页签**：类别页签是定宽网格（每格约 72px）+ 固定 12 号字，
  "Mod Vehicles"（以及物品页签 "Medical/Food"）这类长标签比按钮还宽——IMGUI 的按钮文字
  不裁剪，直接溢出压到旁边页签上。现在每个页签按"塞得下的最大字号"（12 → 8）逐格自适应，
  宽度按字符估算（CJK ≈ 1.0em，拉丁 ≈ 0.56em）。
- **"Mod载具 / Mod物品"页签不再永久为空**：第三方内容原本靠 `ModsLoader.mods_installed`
  发现，而它在主菜单阶段恒为空——探测等 30s 拿到 mod=0 后就把自己标成"就绪"且永不重试，
  于是进战斗后（mod 内容这时才真正可用）页签依旧空着。现在改为**磁盘直扫**
  （`<Steam库>/steamapps/workshop/content/<appid>/*/index.xml` + `<游戏>/Mods`
  + 运行时已装列表兜底），解析出的候选缓存复用，只把**运行时校验**延后到物品库就绪；
  并周期性重扫（有待办 15s、空闲 60s），新订阅的 mod 不重启游戏也会出现。
  彻底移除"mod=0 也算就绪"的终态。
- 连续 5 次校验失败的载具候选（mod 的 bundle 未加载 / prefab 名与清单不符）会放弃该条，
  并在日志里写明放弃的是哪个 id。

2.1.1
- **物品列表的「关键字框」改为「首字母索引」（纯点击）**。
  原因：`GUI.TextField` 在本游戏的 IL2CPP 构建中被裁剪，调用即抛 `Method unstripping failed`，
  异常会**中断整帧 OnGUI**——2.1.0 的实测症状是"子分类页签画出来了，列表全空"。
  索引行只列当前桶/子分类**实际出现过的字母**（另有「全部」），按钮 24px 宽、自动换行，
  完全不依赖键盘，不可能再撞上被裁剪的方法。
2.1.0
- **物品现在可以收藏了**。每个物品行右侧加 ★（与单位行一致），收藏持久化进配置文件，
  与单位收藏共存（`t:<item_id>` 形式）。
- **收藏按类别分组**。选中「收藏」页签后会多出一行**收藏分类子页签**
  （步兵/机枪/坦克/轮式/飞机/火炮 + 武器/弹药/投掷物/装备/医疗食物/其他），
  **只列出你实际收藏过的分类**。单位类与物品类各走各自的列表渲染
  （单位点击=放置，物品点击=拿起），**不做混合列表**，避免误操作。
- **物品子分类**：单是"武器"一桶就约 700 条，故按桶自动出现子页签。
  判定依据**全部来自游戏自己的字段，不猜名字**——`TryCast<Weapon>` 取 `weaponPose`
  得 步枪/手枪，`Interagible.IsWerable()` 得 可穿戴。
- **首字母索引**（物品列表）：见 2.1.1，已取代 2.1.0 的关键字框。
- 切换分类时自动复位子分类与首字母，避免"切过去是空列表"。

2.0.7
- **修复"完全没有物品分类"的真正根因**（2.0.3~2.0.6 修的全是表象）。两处病灶：
  1. **就绪闸门整体移除**。此前每一版都要先等一个条件才开工：「物品库已就绪 **且** items 类别非空」。
     2.0.6 的诊断日志证明这个条件**永远不可能成立**——`ItemsDatabase.Loaded` 恒为 true，
     但 `GetAllItemsOfType(PropType.items)` **永远返回空数组**（连续 154 秒、跨 Menu→LoadingScene→
     Aberdeen 三场景实测）。于是闸门永不开，枚举代码一次都没跑到，协程再健康也没用。
     现在**无条件直接枚举**，拿不到就下一轮重试——从根上消灭"闸门条件猜错"这一类故障，而不是再猜一次。
  2. **问错了类型**。此前调用的是 `GetAllItemsOfType<PropData>`，而该原生方法极可能**按泛型实参过滤**；
     数据库里存的是 **`ItemObject`**（`GetItemObject(id)` 返回的就是它，带 `item_id` 与 `icon`）。
     现以 `ItemObject` 为主数据源、`PropData` 为兜底，两边按 id 去重。
- 诊断日志现在会同时打印**两种类型 × 四个类别**的真实条数，例如
  `物品库可枚举(IO=ItemObject, PD=PropData): items=IO:12/PD:0 weapons=...`，让日志直接说事实、不再靠猜。
- 新增"补漏"重扫：目录建成 20 秒后再扫一遍，防止数据库分批加载导致首轮只拿到一部分。

2.0.6
- **修复"物品页签一个都没有"**：2.0.5 的看门狗**判断逻辑写反了**。它开头是"如果探测正在跑就什么都不做"——可协程被场景切换杀死时，**没有任何代码会把状态复位**（该复位的是已经死掉的协程自己）。于是状态永远停在"正在跑"，看门狗**永远以为一切正常，一次都不会重启它**：探测打印完"未就绪，逐帧轮询等待"就彻底沉默，物品页签自然建不出来。
- **判活方式改为"数协程的帧"，彻底不看时间**：协程每跑一帧就把计数器 +1，看门狗每次检查时对比计数有没有增长——**不增长就说明协程真的没在跑**，立即重启。这个判据与时间无关，场景加载多久、时钟怎么走都骗不过它。
  此前几轮反复翻车，根源都是"用时间流逝当协程死亡的判据"（2.0.3 用 150 秒、2.0.4 用 20 秒心跳），而**场景加载期间主线程被占住、协程停摆但时钟照走**，必然误判。现在这个前提被彻底去掉了。

2.0.5
- 修复"仍然没有物品选项"。2.0.4 改成逐帧轮询方向是对的，但看门狗会把**场景加载期间的正常停摆**误判为"协程已死"并重启；每次重启让重试计数 +1，**6 次触顶后标记为"永久放弃"**——此后即使场景已加载完、数据库早已就绪，也再不会重试。
  现在移除"自动放弃"：探测只有「未开始 / 进行中 / 完成」三态；另加就绪诊断日志，直接说明闸门为何未放行。

2.0.4
- 修复"物品生成仍然不可用"。2.0.3 换掉了错误的就绪判据，但**每 2 秒才轮询一次**，等待窗口正好落在场景切换上被杀掉。现在改为**每帧轮询**，数据库一就绪当帧立刻开始枚举；枚举预算只在数据库就绪之后起算。

2.0.3
- **修复"物品生成整体不可用"**：2.0.2 把物品目录改成向游戏运行时数据库枚举，但**就绪闸门太弱**——只要返回的列表非 null 就放行。而数据库加载完成前，`GetAllItemsOfType` 返回的是**非 null 的空数组**，于是探测被瞬间放行、枚举到 0 条、随即把自己标记为"永久失败"且再不重试。结果物品页签一个都建不起来，**整个物品生成功能是死的**。
  现在探测改为：等游戏自己的 `ItemsDatabase.Loaded` 标志 **且** 实枚举结果非空才放行；未就绪就重试（上限约 2 分钟），不再一次跑死；同时看门狗不再把"正常等待"误判为"协程被场景切换杀死"。
- 诊断：成功时会打一行 `物品目录就绪(来源=运行时 ItemsDatabase 枚举)`，并列出各分类条目数。

2.0.2
- **修复"只有前面有图标的物品能生成，其他全部无效"**：物品目录的来源换了。
  旧版从游戏磁盘上的预制品清单里猜物品 id，但**那份清单的文件名与游戏运行时物品数据库的键并不是同一套字符串**——例如 ArisakaT38、Carcano、Syringe、Thompson_M1928 都确实存在于磁盘，但用它们去数据库取物品会取不到；而恰好键名一致的条目（如 bar_1918、bandages、ToolBox）才能生成。图标来自物品对象本身，所以"有没有图标"无意中成了"能不能生成"的标志。
  现在**直接向游戏运行时数据库枚举**，分类也用游戏自己的物品类型，不再靠猜。列表里只会出现确实能生成的物品。
- **移除全部服装条目**：服装（Uniforms）在游戏里不是可拾取物品，而是换装数据字段，本来就无法作为物品生成——旧版列出的 757 条服装全部无效，现已不再显示。
- 物品目录改为**启动时后台分帧枚举**（每帧最多 3 毫秒），面板打开依旧零卡顿。

2.0.1
- **修复"按下左键选取后直接就放置了"**：结束面板点击的那次鼠标松开被消费后又在本帧继续被判定成一次投放——现在点选物品可以正常"拿起"再拖。
- **修复"很多物品提示无效"**：两个原因——① 61 把枪械（Gewehr43、Springfield_1903、MAS_36、VZ24……）因分类表只认英文枪名而被错归「其他」页签，现已回到武器页；② 清单列的是磁盘上全部预制品，但并非都在游戏运行时物品数据库里注册，现在启动时会逐条核对、把不能生成的从列表剔除。
- **修复拖到单位身上经常失败**：相机射线常常先打中他身前的地面而不是人。现在目标搜索半径按相机距离自动缩放（不再固定 1.6m），且拖到地上时不再因为中间夹着一个士兵就拒绝。
- **补齐物品路径的失败日志**（原先是静默的）：现在"物品无效"一定会在日志里说明原因。

已知限制
--------------------------------
- 单人模式验证；联机仅建议 host 使用
- 飞机地面生成后可能撞毁——小心使用
- 生成单位不保证跨阶段存活
- 任务编辑器创建的自定义小队无法生成：游戏运行时不暴露其成员数据（出生点挂载的班对象是空壳）
- 物品图标是后台惰性解码的：刚打开物品页签滚动时，可能先显示名字、图标稍后出现
