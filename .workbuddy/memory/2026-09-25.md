## SquadCommand 1.4.20 / UniGen 2.5.1 —— UI 自适应 + 提亮 + 全量接入

**用户需求**（原话）："UI 不能是死的，要是可以动态调整的。不要加多余的数值显示等。现在的 UI 太黑了。
全部都要改，不要漏，用游戏原生方式实现。先做一版" + 澄清 **"动态调整指自适应"**（不是手动拖拽/滚轮缩放）。

### 关键决策：自适应 = 跟随游戏原生倍率
- `ResourcesManager.ResolutionMult` 就是玩家在游戏设置里调的 UI 大小，**原生 HUD 全部按它缩放** → 这就是"游戏原生方式"。
- 原 `SquadCmdLogic.ResMult()` 的实现下沉为 `Er2Ui.NativeResMult()`（0.5s 缓存，两 mod 共用一份）；取不到时按 `min(Screen.w/1920, Screen.h/1080)` 兜底（取 min：只按高度会在 21:9 超宽屏低估横向空间）；clamp `[0.75, 1.6]`。
- **不要**自己按屏幕另算一套 —— 那与原生倍率不是同一个量，玩家调了游戏 UI 大小而 mod 不动 = "不像原生"。

### 根因：`const` 令牌让自适应彻底失效
- `Er2Ui` 的 `Pad/Gap/RowH/TabH/FontTitle/FontBody…` 原全是 `const`；更致命的是调用点写
  `private const float PanelW = Er2Ui.PanelW;` —— **编译期钉死**，即使 `Er2Ui.PanelW` 改成属性也推不动。
  光加 `Scale` 字段不解决任何问题。→ 全部改 `=> base * Scale`；字号 int 必须 `RoundToInt`。
- 新增 `SetScale()`（clamp + 值未变早退 + **清 `FitSize` 缓存**）。上一轮我写了调用却漏了实现，编译才暴露（CS0103）。

## SquadCommand 1.4.21 / UniGen 2.5.2 —— 视觉打磨（用户四条反馈）

**用户反馈**（原话）："1.绘制的线条都太粗了 2.颜色浅了，而且只有单一的色块没有设计感，不好看。
3.选中单位后的标记怎么变成箭头了，不好看。4，半透明灰色质感不好。"

### 最关键的教训：改视觉参数前先把**量纲**算清楚
`LineRenderer.widthMultiplier` 是**世界单位**，屏幕像素宽 = `width_m × screenH / (2·dist·tan(fov/2))`。
- 旧代码 `WidthScale = Clamp(dist/30, 0.6, 2.5)` + 基准 0.05~0.12 → 屏幕恒定 ≈ **1.6~3.7px**（且 Bracket 被父缩放放大到 ~13px）。
- **我第一轮同时动了两个耦合因子**：除数 30→60（砍半）+ 基准值砍 55% → 实际落到 **~0.6px，细到看不见**。
  编译/反编译都查不出这种错，只有把量纲算出来才会发现。
- 定案：调用点只写 **1080p 目标像素宽**，`LineWidth(px, dist) = px × 2 × dist × tan(fov/2) / 1080`
  （screenH 在推导里约掉 → **占屏比例与分辨率无关**）。层次 1.1（步兵脚环）… 2.2（集火环）。
  FOV 由 `SetCamFov(cam.fieldOfView)` 注入（GVC / Formation 各一处），取不到按 60° 兜底。旧 `WidthScale` 删除。

### "选中标记变箭头"的真实成因（回源码核实，不是照截图猜——陷阱 82）
角标根对象 `localScale = (radius,1,radius)` 用来放大标记，而 **线宽会被父 `lossyScale` 连带放大**：
载具上 radius ≤ 4.2 → 0.1 m 的线变 ~0.5~1.0 m，而折角臂长只有 0.34×radius ≈ 1 m
→ **两条粗臂糊成实心三角块**。这与"线太粗"是**同一个根因**。
修法：父 scale 恒 `Vector3.one`、半径写进顶点（`Mark.bracketPts` 复用，零分配），臂长 0.34 → 0.42。

### 另外两条
- **半透明在 3D 场景质感差** → 世界标记改 α ≥ 0.80 的**灰阶实色**，层次从 α 移到灰度值
  （`#9AA1A8` → `#8E959C` → `#C6CBD0` → `#E2E6EA` → 纯白）；只给幽灵预览留 α 0.32（预览语义）。
  半透明在**面板**里是优点，在**世界标记**里是缺点。
- **"只有单一色块没设计感"** → 病根是所有面都是纯色填充、没有边框/分隔线/强调条。
  新增 `Frame` / `HLine` / `AccentBar` 三原语 + `Edge`/`EdgeSoft` 令牌；面板加标题条独立底色 +
  标题下分隔线 + 外框 + 列表内凹边框 + 收藏行左竖条。**层次 = 面 + 线 + 条。**
- **"颜色浅了"** → 1.4.20 提亮过头，压回中深灰（`PanelBg #14181D` / `TitleBar #1F252C` /
  `Surface #262D35` / `SurfaceHover #333B45` / `SurfaceActive #46505C`）。

### 验证
- 两 mod 编译 0 error；EN 构建 + 部署 + 打包。
- sha256 部署 == 构建：SC `3CFA3DDCF6B2BA51BAAD239A6BCD49EDD91618470E8D8C98AAC0C3DF7B86D1D3`（222,720 B）；
  UG `B157D4F27084B7E1C183EE7390B8B136DE49FBAC0359DA3F83630E7FF97BC85D`（118,272 B）。

### 新陷阱（已入 guide 89-92 / AGENTS 17g25-17g28）
- **89**：3D 元素的"粗细"参数应是**屏幕像素**，世界单位由代码从视距+FOV+参考分辨率反算。

## SquadCommand 1.4.22 / UniGen 2.5.3 —— 视觉修复（用户第二次："太粗了"）

**用户反馈**："我不是说了太粗了吗，还有为什么还有这么多锯齿。要黑棕色半透明的UI。
还有UI各元素区分不明显，还有背景与文字的重叠。"

### 核心教训：「距离」必须问清参照系
`MarkerCamDist()` 返回的是 `cam.transform.position.magnitude` —— 那是相机到**世界原点**的距离，
**不是到标记的距离**。ER2 地图原点离战区数百米，所以这个值永远是错误的大数。

- 旧版 `Clamp(0.6, 2.5)` 倍率把它盖住了（最多 2.5 倍，看着只是"有点粗"）；
- 1.4.21 我把倍率改成**线性像素公式**后，这个错值直接进了线宽 → 环被填成实心圆盘、
  角标糊成粗 X。**用户两次说"太粗"其实是同一个 bug 的两副面孔。**
- 修法：`CameraGroundDist()` = 视线与地面交点的真实距离（Raycast 命中点，0.1s 缓存），
  `MarkerCamDist()` 与 `MarkerCamDistForFormation()` **共用同一份**。

**通用律：改任何"距离/尺寸/倍率"前，先在注释里写下它的参照系。一个被 clamp 掩盖的量，
去掉 clamp 的瞬间就会暴露它一直是错的。**

### 「环糊成圆盘」的另一半：Ring 也没修父缩放
1.4.22 只修了 `Bracket` 的 `localScale = radius`，`Ring` 还在用同款写法 →
  线宽被 `lossyScale` 放大（载具半径 ≤4.2 倍）。本轮一并修成"父 scale 恒 1 + 半径写进顶点"，
  并加 `lastRadius` 缓存（半径没变就不重写 64 个顶点）。

### 抗锯齿：线/网格不吃 MSAA，靠贴图羽化
- `FeatherTex()`：2×16 竖向 alpha 渐变（两侧各 25% `SmoothStep`）→ 线材质按宽度方向羽化
  （`LineRenderer` 的 UV.y 恰好跨宽度 0..1）。**RGB 必须预乘 alpha**，否则 `Sprites/Default`
  的 `Blend One OneMinusSrcAlpha` 会出黑边。
- `DotTex()`：32×32 径向羽化 + mesh 补 UV 辐射（中心 0.5、边缘 0.5+0.5cos/sin）。
- 环分段 48 → 64。

### 自适应 UI 的两类"错位"（"元素区分不明显" + "文字重叠"）
1. **尺寸**：行高随了 `Scale`，但行**内部**控件仍是硬编码（`90f`/`24f`/`220f`/`20f`/`Pager` 的 30/38/76）
   → 缩放后"行"变大了"行里的东西"没变，文字压到邻行。
2. **间距**：行间距只内嵌在**部分**行高里（`List`/`SubTabs` 有 `+ Gap`，`Crew`/`Preview` 没有）
   → 前者正常、后者紧贴。这不是"忘了加"，是**规则没有单一数据源**。
   修法：行高定义保持纯粹，间距统一在行循环加一次 `y += row.H + (i+1 < rows.Count ? Gap : 0)`，
   面板总高用同一条规则累加。

## SquadCommand 1.4.23 / UniGen 2.5.4 —— 近黑皮革面板 + 线宽回补

**用户反馈**："现在太细了，再粗一点点" / "这完全就是棕色，黑色呢，我要皮革的那种感觉，然后更黑一点" /
"还有菜单最上面的按钮你没发现重叠了吗"。

### 「完全是棕色」的根因：半透明被地形染色
`dst = src×0.82 + terrain×0.18`。面板 α 0.82 叠在**棕色泥地**上，地形颜色参与混合 →
**面板就永远是棕的，压配色板没有用**（压的只是那 82%）。
"半透明"与"黑"在亮色背景上是**互相矛盾**的需求，必须取舍。

修法：**α 0.82 → 0.92**（保住"透出战场"的观感，同时压住染色）+ 底色压到近黑 `#0C0906`。

### 「皮革的那种感觉」：质感来自纹理，不是颜色
一个近黑矩形仍然只是"一块色板"。皮革观感 = **细微斑驳 + 受光边缘**。
- `LeatherTex()`：64×64 程序化 value noise，两层倍频（`PerlinNoise(x*0.09)` 大皱褶 +
  `PerlinNoise(x*0.37+31.7)` 细粒），灰度刻意 0.34~0.66（**只压暗不泛灰**），
  `wrapMode=Repeat` + `hideFlags=61`（陷阱 12）。
- `Leather(Rect, alpha)`：`GUI.DrawTextureWithTexCoords(rect, tex, new Rect(0,0,w/tw,h/th))`
  平铺，默认 0.10。
- `PanelBase(Rect)`：近黑填充 + 皮革 + **顶部 1px 受光边**（这条边让面板像"一块有厚度的皮"）。
- 接入：GenPanel 面板底 + 标题条(0.14)、BackpackPanel 底板 + 标题条、HUD 提示条(0.10)。

### 「最上面的按钮重叠」：容器高度 ≥ 内容 + 上下留白
标题条高 26px，而内容"从 +8 开始、高 22px" → 按钮底 30 > 26 → **压在标题条下的分隔线上**。
修法：Title 行高 26 → `34f * Scale`（8 上留白 + 22 内容 + 4 下留白）。
**行高 = 上留白 + 内容高 + 下留白，别凭感觉给。**

### 线宽 +40%（"太细了"）

IMGUI 的粗体只有两个来源：

**修法：描边双绘**（新增 `Er2Ui.LabelOutlined`）：
```csharp
GUI.contentColor = new Color(0f, 0f, 0f, 0.9f);

GUI.Label(offsetRect(-o, -o), text, style);
GUI.contentColor = fg;                        // 正文（fg 纯白，由 style.textColor 定色）
GUI.Label(r, text, style);
```
**描边不依赖字体变体 → 一定生效**；成本 3 次 Label/处，可接受。

### ② 幽灵 = shader 取样来源搞错（陷阱 108）
`ghostMat.color = WGhost`（含 alpha 0.32）**完全无效**，幽灵渲染成**实心亮白**。

原因：材质用 `Sprites/Default`，它的片元是 `tex2D(_MainTex, uv) * IN.color` ——
**读顶点色**（Sprite 渲染器会填），而 `MeshRenderer` 用的普通 Mesh **没有顶点色**（≡ 白），
且该 shader **根本没有 `_Color` 属性**。

修法：shader 优先链改 `Particles/Standard Unlit`（unlit + 读 `_Color` + 支持 alpha）

→ URP Unlit → `Hidden/Internal-Colored`；

`WGhost`：`#B8BCC0@0.32` → **`#8C9196@0.20`**。
