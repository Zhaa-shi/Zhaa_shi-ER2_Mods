# 2026-09-25

## SquadCommand 1.4.20 / UniGen 2.5.1 —— UI 自适应 + 提亮 + 全量接入

**用户需求**（原话）："UI 不能是死的，要是可以动态调整的。不要加多余的数值显示等。现在的 UI 太黑了。
全部都要改，不要漏，用游戏原生方式实现。先做一版" + 澄清 **"动态调整指自适应"**（不是手动拖拽/滚轮缩放）。

### 关键决策：自适应 = 跟随游戏原生倍率
- `ResourcesManager.ResolutionMult` 就是玩家在游戏设置里调的 UI 大小，**原生 HUD 全部按它缩放** → 这就是"游戏原生方式"。
- 原 `SquadCmdLogic.ResMult()` 的实现下沉为 `Er2Ui.NativeResMult()`（0.5s 缓存，两 mod 共用一份）；取不到时按 `min(Screen.w/1920, Screen.h/1080)` 兜底（取 min：只按高度会在 21:9 超宽屏低估横向空间）；clamp `[0.75, 1.6]`。
- **不要**自己按屏幕另算一套 —— 那与原生倍率不是同一个量，玩家调了游戏 UI 大小而 mod 不动 = "不像原生"。

### 根因：`const` 令牌让自适应彻底失效
- `Er2Ui` 的 `Pad/Gap/RowH/TabH/FontTitle/FontBody…` 原全是 `const`；更致命的是调用点写
  `private const float PanelW = Er2Ui.PanelW;` —— **编译期钉死**，即使 `Er2Ui.PanelW` 改成属性也推不动。
  光加 `Scale` 字段不解决任何问题。→ 全部改 `=> base * Scale`；字号 int 必须 `RoundToInt`。
- 新增 `SetScale()`（clamp + 值未变早退 + **清 `FitSize` 缓存**）。上一轮我写了调用却漏了实现，编译才暴露（CS0103）。

### 接入范围（"不要漏"）
- SC：`GodViewController.DrawHud`（提示条 `1400px → ScreenFit(1400)`；HUD 位置/尺寸/框选描边 × Scale；控制/分队/合并按钮矩形 × Scale）、`InfoPanel`、`BackpackPanel`（Cell/Gap/Margin/TitleH/WinW/WinH 属性化；倍率变化时**保留玩家拖动位置**只改尺寸 + clamp 回屏幕；菜单 `MenuW/MenuRow` 与命中判定**共用一份**；tooltip/拖拽幽灵/格子内像素量 × Scale）。
- UG：`GenPanel`（属性化 + 字母行单一定义）、`ItemDragger`（BadgeRect 560px → `ScreenFit`；残留绿色清零）、`GenRunner.Draw()` **总入口**加 `AutoScale()`（携带/放置两支不经过 `GenPanel.Draw()`，只放那里会永远用旧倍率）。
- 自适应入口合计：SC 3 处、UG 2 处。

### 配色提亮（"现在的UI太黑了"）

## SquadCommand 1.4.21 / UniGen 2.5.2 —— 视觉打磨（用户四条反馈）

**用户反馈**（原话）："1.绘制的线条都太粗了 2.颜色浅了，而且只有单一的色块没有设计感，不好看。
3.选中单位后的标记怎么变成箭头了，不好看。4，半透明灰色质感不好。"

### 最关键的教训：改视觉参数前先把**量纲**算清楚
`LineRenderer.widthMultiplier` 是**世界单位**，屏幕像素宽 = `width_m × screenH / (2·dist·tan(fov/2))`。
- 旧代码 `WidthScale = Clamp(dist/30, 0.6, 2.5)` + 基准 0.05~0.12 → 屏幕恒定 ≈ **1.6~3.7px**（且 Bracket 被父缩放放大到 ~13px）。
- **我第一轮同时动了两个耦合因子**：除数 30→60（砍半）+ 基准值砍 55% → 实际落到 **~0.6px，细到看不见**。
  编译/反编译都查不出这种错，只有把量纲算出来才会发现。
- 定案：调用点只写 **1080p 目标像素宽**，`LineWidth(px, dist) = px × 2 × dist × tan(fov/2) / 1080`
  （screenH 在推导里约掉 → **占屏比例与分辨率无关**）。层次 1.1（步兵脚环）… 2.2（集火环）。
  FOV 由 `SetCamFov(cam.fieldOfView)` 注入（GVC / Formation 各一处），取不到按 60° 兜底。旧 `WidthScale` 删除。

### "选中标记变箭头"的真实成因（回源码核实，不是照截图猜——陷阱 82）
角标根对象 `localScale = (radius,1,radius)` 用来放大标记，而 **线宽会被父 `lossyScale` 连带放大**：
载具上 radius ≤ 4.2 → 0.1 m 的线变 ~0.5~1.0 m，而折角臂长只有 0.34×radius ≈ 1 m
→ **两条粗臂糊成实心三角块**。这与"线太粗"是**同一个根因**。
修法：父 scale 恒 `Vector3.one`、半径写进顶点（`Mark.bracketPts` 复用，零分配），臂长 0.34 → 0.42。

### 另外两条
- **半透明在 3D 场景质感差** → 世界标记改 α ≥ 0.80 的**灰阶实色**，层次从 α 移到灰度值
  （`#9AA1A8` → `#8E959C` → `#C6CBD0` → `#E2E6EA` → 纯白）；只给幽灵预览留 α 0.32（预览语义）。
  半透明在**面板**里是优点，在**世界标记**里是缺点。
- **"只有单一色块没设计感"** → 病根是所有面都是纯色填充、没有边框/分隔线/强调条。
  新增 `Frame` / `HLine` / `AccentBar` 三原语 + `Edge`/`EdgeSoft` 令牌；面板加标题条独立底色 +
  标题下分隔线 + 外框 + 列表内凹边框 + 收藏行左竖条。**层次 = 面 + 线 + 条。**
- **"颜色浅了"** → 1.4.20 提亮过头，压回中深灰（`PanelBg #14181D` / `TitleBar #1F252C` /
  `Surface #262D35` / `SurfaceHover #333B45` / `SurfaceActive #46505C`）。

### 环境坑（本轮新增）
**bash `python -c "..."` 里写反引号会被 shell 当命令替换执行** → markdown 代码标记被静默吃掉，
文件内容损坏且脚本仍"成功"退出（写台账时踩到，只能 `git checkout` 恢复重做）。
**含反引号的批量文本改动一律写成 .py 脚本文件再执行**，或在 bash 双引号里用 `\`` 转义。
