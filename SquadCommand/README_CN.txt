ER2 Battlefield Commander v1.4.37
================================

一款给 Easy Red 2 增加「RTS 上帝视角小队指挥」的 BepInEx 插件，鼠标操作逻辑参照《地狱之门：东部前线》。

【1.4.37 最后一处灰色文字 + 信息面板去底板】
· **提示条的文字是最后一处灰色。** `HudStyleSmall()` 与背包的 `tipStyle` 仍硬编码着
  军绿时代的颜色 `(0.85, 0.9, 0.85)`——它们**不经过 `uiText`**，所以 1.4.36 的文字统一漏掉了它们
  （陷阱 113 的"旁路"又现身）。两处都改为 `Er2Ui.Text`。
  **全项目扫描**所有 `MakeLabel` / `MakeButton` 调用确认：不再有任何非白色文字源。
· **单位信息面板去掉底板**，与游戏自带的左上角选中信息同款：白字 + 阴影直接叠在场景上。


【1.4.36 文字统一纯白 + 信息栏与提示条互斥】
· **文字还是灰色的原因**：HUD 的文字色来自**配置文件**，而 cfg 不会自己更新（陷阱 109）——
  你本地的 `colorText` 还是旧灰值。现在 `colorText` 加入迁移链（旧值 #E8E8E8 / #F1EBE2 / #F0F0F2
  → #FFFFFF），并且**更重要的是：HUD 文字色源改为直接读 `Er2Ui.Text`**——
  指挥官 mod 与通用生成从此共用同一个纯白，三个颜色配置保留但不再被读取。
· **信息栏与底部提示条在竖轴上互斥**：没选中任何单位时，信息面板整个不画（提示条显示）；
  有选中时信息面板出现（提示条让位）——不再同时存在。
· `colorBase` 默认改为 `#00000080`（黑 50%，与新的透明度一致），迁移链同步。


【1.4.35 修重叠 + 背景透明度 50% + 文字纯白】
· **左下信息面板和小队列表不再压到底部提示条上。** 上一轮做"对称"时我把两块的底距都改成了
  14px——但提示条的**顶边在离屏幕底部 30px** 处，14px 的底距让两块直接穿过去（你的截图）。
  现在两块底距都是 **36px**（提示条 30 + 6 间隙），左右依旧对称。
· **面板透明度改为 50%**（你指定的）：`uiPanelAlpha` 默认 0.72 → 0.50（cfg 范围下限降到 0.40），
  提示条自己的 `Scrim` 也同步到 50%。历史默认值 0.85 / 0.72 都加进了迁移链。
· **文字全部纯白**——次要文字也从 `#E4E4E8` 提到 `#FFFFFF`。悬停反馈用一个新的专用色
  （`TextHover #B4B4BA`）实现——如果悬停还引用那个已经改成纯白的"次要文字色"，
  "文字变暗"的反馈就会再次悄悄失效。


【1.4.34 左右对称 + 悬停反馈恢复】
· **删掉了那个悬停提示框**（按你的要求），并把悬停反馈恢复为原样：
  悬停在页签或列表条目上时，**文字变暗**——这是描边重构时丢掉的老行为
  （描边画的字感知不到 GUI 样式的 hover，现在逐行手动判定）。
· **左下角单位信息面板改为动态高度**。原来固定 190px 高，内容只有几行时下面是一大片空白
  （你的截图）。现在每帧实测内容底部并自适应面板高度，且**底边距屏幕 14px**——
  与右下角小队列表相同，左右两块对称。


【1.4.33 配置迁移 + 幽灵全材质槽 + 描边加强】
· **"UI 没改完"的原因在你的配置文件里。** BepInEx 首次运行写下 `.cfg` 后，**不会**因为代码里
  默认值改变而重写它——所以你这个文件里的 `colorBase` / `colorHover` 还是很多版本前的旧值
  （军绿那套）。面板走的是共享色板所以是新的，HUD 按钮却保留着旧色。
  现在加了**自动迁移**：值若仍命中历史默认值（说明你从未手动改过），就更新为当前默认值；
  你自己改过的值一律不动。
· **幽灵预览现在会替换**每一个**材质槽。** 原代码用 `renderer.sharedMaterial`，它只改第 0 个槽；
  士兵和载具都是多槽模型（身体 / 装备 / 头盔 / 履带），第 1 个之后的槽位一直保持原材质——
  这就是"装备还是原色"的原因。现在所有槽位都会被填成幽灵材质。
· **文字描边加强**：描边由两方向改为**四方向**，列表行文字再放大一号，
  让文字与背后的面板明确分开。


【1.4.32 悬停提示恢复 + 幽灵修复 + HUD 统一底板】
· **悬停提示回来了。** 1.4.30 那轮为了让文字能描边，把控件内容从文本换成了 `GUIContent.none`——
  顺带把 tooltip 通道也清掉了，于是页签和条目悬停什么都不显示。现在控件改为携带
  `new GUIContent("", tooltip)`（文本为空、tooltip 保留），面板在本帧末尾自绘提示框。
· **幽灵预览修好了——原来渲染成了实心白。** 材质用的是 `Sprites/Default`，它的片元是
  `纹理 × 顶点色`：读的是**顶点色**而不是 `_Color`。Mesh 没有顶点色，所以 `ghostMat.color`
  完全不生效，幽灵一律变成不透明白色。现在 shader 优先链改为 `Particles/Standard Unlit`
  （unlit、读 `_Color`、支持 alpha）并显式配置 Fade 混合；幽灵色调同时调得更暗更透。
· **单位信息面板加了背景，并与小队列表对齐。** 左下角那块原本完全没有底板（文字直接叠在战场上）。
  现在它的左边缘内缩量与右侧小队列表的内缩量一致，两块 HUD 左右对称。
· **整个 HUD 统一成一块底板。** 你喜欢的底部提示条背景（纯黑 72%）抽成了共用函数
  `DrawHudPlate`，底部提示条、小队列表、单位信息面板**共用同一套**（同样的填充 + 皮革纹理 + 描边）。
  HUD 按钮默认色也统一成同一个纯黑 72%。


【1.4.31 非中文游戏的捡枪修复 + 光标更清晰 + UI 统一】
· **"士兵还是隔空捡枪"这次真正修好了，根因是语言。** 1.4.17 的修法靠判断交互文案是否以中文
  "拾起"开头；英文版里文案是 "Pick up ..."，判断**必然失败** → 该条目回落到原生 `Call()`，
  而原生接口**完全没有距离校验**。现在改用 **`Interaction.classType`**（发起交互的组件——
  对地面物品就是物品本身）判断，**与显示语言无关**，并保留中英双语前缀作为兜底。
· **光标不糊了。** 原纹理 32×32——正是 Windows 硬件光标的上限，一旦系统 DPI 缩放或游戏全屏缩放
  就会被拉伸成糊的。现在 64×64，Unity 会自动改用**软件光标**按屏幕分辨率绘制。
· **光标恢复分色。** 1.4.19 为配合灰黑 UI 把光标所有状态压成了灰阶（只剩敌军红、工事橙），
  看起来就像"不能变色了"。现在逐状态配色：友军青绿 / 敌军红 / 可驾驶载具亮青 / 建筑灰白 /
  工事橙 / 可交互物品黄 / 默认白。
· **指挥官 mod 与通用生成现已共用同一套面板风格**：同一套面板色令牌、同款皮革纹理、
  同样的顶部受光边；HUD 按钮描边也改用共享边框令牌（原来是拿文字色描的）。


【1.4.30 文字改描边 + 面板色对齐 HUD 提示条】
· **文字改为描边，不再依赖加粗。** `FontStyle.Bold` 只有在**字体自带粗体字形**时才生效，
  而游戏字体很可能只有单一字重——那种情况下 IMGUI 会**静默忽略**（不报错、不生效）。
  这正是上一版"加粗 + 放大"看起来毫无变化的原因。现在行文字与页签文字改为：
  先画一圈暗色偏移副本，再把白色正文压上去——**描边不依赖字体变体，一定生效**。
  行文字字号同时提到 `FontBody + 3`。
· **面板颜色改成你指的那条底部 HUD 提示条的配色。** 所有面的**蓝调去掉**（三通道相等），
  面板不透明度默认改为 **0.72**——与 HUD 提示条一致，因此面板会像那条一样带出地形色，
  而不再发冷。


【1.4.29 文字加粗 + 行分隔线 + 继续提亮】
· **列表文字加粗并放大一号**。对比度其实从来不是问题（纯白叠在 #1A1A22 上约 15:1）——
  是 12px 常规体的**笔画太细**，在深色面上"感觉不亮"。把行文字加粗加大才是对症的做法。
· **每一行都画分隔线**。此前横线只在**行与行之间**画，所以只有一条目的列表一条线都没有
  ——收藏看起来"横线没了"就是这个原因。收藏的文件夹列表原先完全没有横线，现在也补上了。
· **收藏星星 14 → 17px、加粗、金色提亮到 #FFE81A**。小号 ★ 字形笔画极细，
  即使颜色正确也显得暗。
· **底色再提亮一档**（面板 #1A1A22、标题条 #26262F、控件 #32323C、行底 #24242C / #2E2E38），
  列表底的不透明度也降了下来。


【1.4.28 面板提亮 + 斑马纹】
· **面板整体提亮一档**（面板 #121218、标题条 #1C1C24、控件 #26262E、行底 #1A1A20），
  仍是中性黑，文字保持纯白。
· **列表加斑马纹（交替行底）**：小字号 + 仅一条 1px 分隔线时，行与行很难跟读；
  现在相邻行交替两种底色——这是列表可读性最有效的一招。


【1.4.27 前景改纯白 + 底部文字溢出修复】
· **透明现在只作用于背景。** 此前边框与分隔线的不透明度也被面板透明度设置带着走——
  调透明度会连轮廓一起变淡，对比度就是这么丢的。现在**面**（面板/标题条/行/选中）跟随
  `uiPanelAlpha`，**文字与线条完全不透明**。
· **文本与线条改成白色**（文字 #FFFFFF、边框与行分隔线纯白），在黑底上任何地形背景前都清晰。
· **收藏星星太暗** —— 根因：`GUI.contentColor` 与 `GUIStyle.normal.textColor` 是**相乘**关系，
  而星标样式用的是灰色文字色，把金色乘成了浑浊的 #CAA84D。现在样式改纯白，金色准确显示
  （并提亮到 #FFD800）。
· **底部帮助文字不再溢出。** 真正的原因是**横向**而非纵向：英文文案约 99 字符，
  12 号字下约 570px，而面板内宽只有约 450px。现在同时缩短文案 + 用专用样式按可用宽度自动缩字号。


【1.4.26 标记线宽回到世界空间（自然的近大远小）】
· **"近处小、远处成一坨大圆盘"的根因找到了。** 标记半径是**固定世界尺寸**
  （从各单位 Collider 量出，步兵夹在 0.35~1.1m、载具 1.6~4.2m），所以圆环本来就随距离自然缩小。
  但线宽用的是**屏幕像素恒定**——这意味着它的**世界宽度随距离增大**：
  60m 处 1.5 像素已经约 0.10m，到 200m 附近约 0.34m，而环半径只有 0.6m → **环被填实、读作实心圆盘**。
  **把"世界尺寸"和"屏幕尺寸"两套尺度规则混用，才是真正的 bug。**
· **线宽也改用固定世界单位**（步兵脚环 0.032m、角标 0.042/0.060m、集火环 0.065m、
  虚线 0.030~0.038m、阵型 0.048/0.060m）。线宽从此与它所属的标记同尺度：近粗远细，
  任意镜头距离下两者比例恒定。代价是有意的：极远处线会细到亚像素——那就是真实透视的样子。
  `[Markers] markerLineWidth` 仍可整体缩放。


【1.4.25 对比度 + 底部留白】
· **标记线宽回退到 1.4.23 的数值**（步兵脚环 1.5、角标 2.2/2.6、集火环 3.0、
  虚线 1.7/1.8、阵型 2.4/2.5）。"太细"的观感来自镜头拉得太近：标记半径是世界固定值，
  拉近后圆环在屏幕上占很大面积，而线宽被我做成"屏幕像素恒定"——线宽/孔径的比例就掉下来了。
  像素恒定在跨分辨率的意义上仍然正确，但**"粗不粗"的感知取决于标记自身的屏幕尺寸**。
  极近距离若仍嫌细，用 `[Markers] markerLineWidth` 统一放大。
· **修掉最下面那行字压出面板边缘。** 数学上留了底边距，但只有约 8px——这在视觉上就读作"在外面"。
  底部留白改为 18px（顶部仍 8），帮助行行高 34 → 38。
· **对比度一轮**：面板描边更亮（#555560）且加粗到约 2px，在石头/水泥这类亮背景上也有清晰边界；
  选中底更亮（#52525E）、行底更沉、行分隔线 10% → 15%、列表底更实——
  文字/行/选中态各自分明，不再糊成一片灰。


【1.4.24 中性半透明黑 UI + 标记再加粗】
· **标记线再上调约 60%** —— 步兵脚环 1.5 → 2.4、选中角标 2.2/2.6 → 3.5/4.2、
  集火环 3.0 → 4.8、路线/登车虚线 1.7/1.8 → 2.7/2.9、阵型 2.4/2.5 → 3.8/4.0。
  屏幕粗细仍与分辨率无关。
· **面板改中性黑，不再带棕色**：所有结构色现在 R=G=B（暖棕彻底去掉），
  皮革噪声纹理也去了暖调——在中性黑底上叠暖色只会发黄。
· **面板不透明度交给你调**：`UI/uiPanelAlpha`（默认 0.85，范围 0.55~1.0）。
  "透"和"黑"本来就是互相拉扯的一对——半透明面板叠在棕色泥地上必然带上地形色。
  与其替你猜一个折中值，不如把这一轴做成配置项。1.0 = 完全不透明。


【1.4.23 近黑皮革面板 + 标记加粗】
· **距离修好后线又偏细了** —— 基准像素宽整体上调约 40%（步兵脚环 1.1 → 1.5、
  选中角标 1.6/1.9 → 2.2/2.6、集火环 2.2 → 3.0 …）。屏幕粗细仍与分辨率无关。
· **UI"完全就是棕色"的原因：半透明被地形染色。** α 0.82 时面板会透出棕色泥地，
  再怎么调色板也黑不下来。现在面板不透明度 0.92、底色压到近黑（#0C0906），只留极轻的暖调。
· **皮革质感。** 一个近黑矩形仍然只是"一块色板"，所以面板底改为三层：
  近黑填充 + 64×64 程序化皮革噪声纹理（两层倍频，确定性）以 10% 透明度平铺 + 顶部 1px 受光边。
  **是纹理和受光边读作"皮"**，不是颜色。
· **修掉面板最上面按钮的重叠。** 标题行原本高 26px，但内容从 +8 开始、按钮高 22px →
  Clear / × 两个按钮越过了标题条下的分隔线。现在标题行高 34px（8 + 22 + 4）。
· cfg 默认色同步压黑（#0F0B08 / #2A2017）。


【1.4.22 修复 + 黑棕 UI】
· **线宽爆表的真因：相机距离取错了。** 标记线宽由相机距离推导，而这个距离原先用
  `cam.transform.position.magnitude`——那是相机到**世界原点**的距离，不是到标记的距离。
  ER2 地图原点离战区可达数百米，所以这个值永远是个错误的大数。旧版靠 `Clamp(0.6, 2.5)`
  倍率把它盖住；1.4.21 改成线性像素公式后，这个错值直接进了线宽——环被填成实心圆盘、
  选中角标糊成粗 X。现在改为"视线与地面交点的真实距离"（0.1s 缓存，GodView 与阵型标记共用一份）。
· **圆环不再用父对象缩放定尺寸。** 环原先仍用 `localScale = radius` 控制大小，而 LineRenderer
  线宽会被父级 `lossyScale` 连带放大——载具上环被放大到 4.2 倍。现在半径写进顶点
  （与角标同款修法），线宽是纯粹、可预测的世界值。
· **线条与圆点抗锯齿。** 线网格不吃 MSAA（截图锯齿明显）。现在线条沿宽度方向采样一张羽化纹理
  （两侧各 25% 平滑过渡），圆点用径向羽化圆盘，边缘从"台阶"变"干净"。圆环分段同时 48 → 64。
· **黑棕半透明 UI。** 配色由冷灰改为**暖黑棕 + 半透明**（面板 #1E1813@0.82、标题条 #2A2119@0.86、
  控件 #32271E@0.84、选中 #584331@0.96）。暖色在泥土/草地背景上协调得多，且面板能透出战场。
· **元素区分明显了。** 每个页签、阵营按钮、乘员按钮都加描边（未选中暖棕 / 选中暖白）；
  列表行之间加极细分隔线；面板描边与分隔线改暖棕——在黑棕底上才真正读得出边界。
· **文字不再与背景重叠。** 乘员 / 提示 / 标题 / 阵营 / 列表 / 分页这些行此前仍用硬编码像素，
  没有乘自适应倍率；而且行间距只内嵌在**部分**行里，导致乘员行与提示行紧贴在一起。
  现在这些尺寸全部随倍率，间距统一在行循环里加一次。
· 补全 16 条此前回退中文的英文 cfg 描述。


【1.4.21 视觉打磨】
· **线宽改用「像素」定义，不再用世界单位**：`LineRenderer.widthMultiplier` 是世界单位，
  写死一个数必然近粗远细；而用「距离倍率」糊弄又会随分辨率跑偏——1440p 下粗 1.33 倍、
  4K 下粗 2 倍（这正是「线太粗」的一大来源）。现在调用点只写 1080p 下的目标像素宽
  （1.1 最细 ~ 2.2 强调），由 `Er2Ui.LineWidth` 按当前视距和相机 FOV 反算世界单位。
  结果：任意视距、任意分辨率下屏幕粗细恒定。
· **选中角标不再是「箭头」**：成因是回代码查出来的，不是照截图猜的。
  角标根对象原先被缩放到 `radius`，而 LineRenderer 线宽会被父级 `lossyScale` 连带放大——
  载具上（半径最大 4.2）一条 0.1m 的线被放大到约 0.5~1.0m，而折角臂长只有约 1m，
  两条粗臂直接糊成一个实心三角。现在根对象缩放恒为 1、半径写进顶点；
  折角臂长同时 0.34 → 0.42（占半径比例），L 形更明确。
· **世界标记从「半透明」改为「灰阶实色」**：α 0.26~0.48 的半透明灰会被草地/雪地/沙地吃掉，
  颜色随背景漂移、边界发虚。现在所有世界标记改为近实色灰阶（α ≥ 0.80），
  层次靠灰度值拉开（#9AA1A8 → #C6CBD0 → #E2E6EA → 纯白），不再靠透明度。
  只有幽灵预览保留半透明——那正是它读作「预览」的依据。
· **面板补上真正的结构，不只是色块**：此前所有面都是纯色填充，层次只靠明度差硬撑，
  在亮背景下会糊成一片。新增三个原语——`Frame`（描边）、`HLine`（分隔线）、
  `AccentBar`（选中竖条），并加了独立的标题条底色、列表内凹边框、收藏行左侧竖条。
  层次从「只有面」变成「面 + 线 + 条」三维。
· **配色压回中深灰**：1.4.20 那次提亮过头（反馈「颜色浅了」）。面板 #14181D、
  标题条 #1F252C、控件 #262D35、悬停 #333B45、选中 #46505C，逐级拉开 8~14 级明度差——
  有了这个梯度，新加的描边才读得出来。
· **清掉死代码**：旧的 `WidthScale` 经验倍率、角标路径里每帧白建的 `float[4]`、
  以及两个残留的分辨率缓存字段。

【1.4.20 自适应 UI】
· **UI 自适应（不需要手动缩放）**：面板、HUD 文字、底部提示条、背包格子、悬浮提示、右键菜单
  全部跟随**游戏自己的 UI 大小设置**（`ResourcesManager.ResolutionMult`，读不到时按屏幕分辨率兜底）。
  在游戏设置里调 UI 大小，本 mod 与通用生成一起缩放——不用拖拽、没有多余数值框、不需要改 cfg。
  倍率夹在 0.75x – 1.6x。
· **面板不再是"死的"**：`Shared/Er2Ui.cs` 里的尺寸/字号令牌原先是编译期常量，分辨率怎么变都推不动。
  现已改为随倍率联动的属性；倍率变化时样式自动重建（各面板各判各的上次倍率，不会再互相抢清）。
· **定宽元素收敛进屏幕**：底部提示条原先硬编码 1400px，在 1366 宽屏上会溢出屏幕外，现已修掉。
· **灰黑配色提亮**：上一版偏黑，深色面在亮背景下压成一坨。现在面板→标题条→控件→行→选中
  逐级拉开 +8~14 级明度差，层次清楚了，但不回到军绿。
· **通用生成的遗留绿色一并清掉**：携带徽标底色（旧军绿）、拖拽目标环（原来是亮绿，改白）
  与生成反馈文字色都并入共享配色。

【1.4.19 界面重绘】
· **灰黑单色 UI**：面板/列表/按钮全部改用中性灰黑（`Shared/Er2Ui.cs`），层次靠明度而非色相区分。
  设 `UI/uiMono=false` 可回退旧版军绿配色。
· **世界空间标记重绘**：选中标记由四段 45° 圆弧（读起来像气象符号）改为**直角四角括号**，
  这是 RTS 通用语言。所有地面标记（友军脚环、集火环、移动目标点、路线/登车线、阵型标记）改为
  **白色 / 半透明灰**，靠「明度档 + 虚线节奏 + 形状」区分语义。
· **路线与登车线终于能分开了**——此前两者用的是**完全相同的颜色字面量**。
  现在路线 = 暗色长虚线，登车线 = 亮色短虚线。
· 标记脉动相位按 key 错开（此前所有标记同频同相一起呼吸）。
· 线宽按相机距离补偿（LineRenderer 线宽是世界单位，远处会细成一丝）。
· 名签加深色底板（压在雪地/天空上也能读清）。
· 光标各状态改灰阶（仅敌军保留红、火力点保留橙）。
· **新增 14 项视觉开关**（`[Markers]` + `[UI]`），上述每一项都可关：
  markersEnabled / showFriendlyRing / showSelectedBracket / showFocusRing / showMoveTarget /
  showPathLines / showFormationMarkers / showNamePlates / markerPulse / markerScale / markerLineWidth /
  markerThroughWall / markerColorMode (Mono|Semantic) / uiMono。

【1.4.18 内部调整】
· 无玩法与视觉变化。HUD、信息面板、背包的文字样式改为统一走共享 UI 工具层（`Shared/Er2Ui.cs`），
  不再各自手写 `GUIStyle`。字号、对齐、配色与此前完全一致——这是为两个 mod 重绘成统一观感做的地基。

【1.4.17 修复】
· 拾取地面**枪械**不再隔空吸进背包。地面枪械是多交互物品（原生菜单有"拾起置于右手"等条目），
  右键会弹交互菜单——此前点菜单里的拾起条目会**原样执行原生交互，无视距离**
  （"隔着半张地图把枪吸走"），而普通物品是派兵走过去捡。
  现在菜单里的拾起条目汇入与普通物品**完全相同的链路**：联动半径内即时拾取，
  超出则派最近的选中士兵走过去、到达再捡。其他原生交互（补充弹药等）不受影响。

【1.4.16 修复】
· 附属 mod（如通用生成）可声明其全屏互斥是"放置/拖放手势"而非"UI 面板"
  （新契约 `externalCameraPass`）。手势生效期间相机继续响应滚轮/中键；
  点击仍被吞掉，放置落点不会漏进原生框选/指令。

【1.4.15 修复 + 兼容】
· 上帝视角下打开原生设置/暂停菜单（ESC）后，相机输入不再继续响应：
  此前 WASD 平移、滚轮缩放、中键旋转、Q/E 升降都会穿透菜单继续生效（玩家反馈最明显的是
  "打开设置后转滚轮，视角还在跟着动"）。
  规则：菜单打开 → **全部**相机输入冻结；只是指针停在我们的面板（小队列表/信息面板/背包窗口/
  外部 mod 面板）上 → 只冻结鼠标驱动的操作（滚轮/中键），键盘 WASD、Q/E 照常可用。
· 兼容 Advanced Combat Movement（Responsive Orders）：该 mod 对
  Squad.SetHoldFireOrder(false, ...) 加了 Prefix，当"小队长 == 当前操控兵"时直接吞掉调用
  → 下过移动令的小队可能**永久停火**。现在恢复开火改为
  「调用 → 回读校验 → 仍停火就直写原生 holdFire 字段」（字段写入不受 Harmony 前缀影响）。
  没装该 mod 时行为完全不变。

【1.4.14 性能优化】
· 友军小队枚举带 0.3s 缓存——原实现每次都要遍历**全场景所有生物**并逐个做类型转换，
  进入 RTS / 接管 / 编组等流程里会被连续调用多次，是大战场上数百毫秒卡顿感的主要来源。
· 分辨率倍率、主相机、玩家操控单位、本阵营阵营串全部改为短周期缓存
  （原本在每一帧、乃至每个士兵每一帧被反复做 interop 读取，战场上可达每秒上万次）。
· 每帧的选中标记绘制不再分配临时列表、不再逐单位做组件反查。
· 行为零变化：缓存只做加速，所有判定的最终依据仍是实时状态。

【进入/退出】
· F9：进入上帝视角（主要用于进入 RTS；全军覆没等紧急情况下可再次按 F9 退出）。
· 正常退出：先框选/选中要接管的单位 → 点顶部中央 [控制该小队] 按钮，随机接管一名存活成员，回到第一人称。
· RTS 中已经下达的移动、集火、登车和车辆移动任务，退出 RTS 后仍会继续执行。

【上帝视角操作（地狱之门式）】
· WASD 移动、滚轮缩放、鼠标中键按住旋转视角、Q/E 升降。
· 左键单击友军士兵/载具 = 选中（步兵=单兵，载具=整车组）；左键点击敌军/空白 = 清空选择。
· 双击友军士兵 = 选中该单位所在整个小队。
· 长按左键框选 = 框内友军临时选中；不会自动拆散原生小队。
  只有显式点击顶部 [分队] 才会创建真实新小队；载具车组不拆散整体纳入选择；Shift+框选 = 追加。
· 右键短按 = 下指令：地面=移动（仅选中的单位）、敌军=持久标记集火（只指定打击目标，不自动推进）、
  友军/中立载具或火力点=直接上车/进入（无菜单）、车内友军=补员上车、
  **徒步友军=最近的选中士兵走过去，到达后打开双方背包（1.3.4）**、
  **地上物品=有多个原生交互时弹它的交互菜单（弹药箱=补充弹药），否则拾取——联动半径内即时捡起，
  超半径则最近的士兵走过去到达后捡（1.4.1）**、建筑/房屋=选中步兵进入并找掩体防守。
· 右键双击（同一目标 0.6s 内） = 原生「前往并防守」（HoldArea）：对选中单位所在原生小队
  单条命令下达，Mod 不做额外编排。
· 右键长按（0.35s）并拖动 = 阵型箭头（地狱之门式，1.2.19 起）：
  阵型线中心 = 长按点，线方向垂直于箭头，线总长 = 箭头长度，单位面向箭头所指方向。
  - 目标区附近有原生掩体点（沙袋/墙沿/Combat Cover 道具等）时，步兵逐一分配掩体并走原生 findCover 进掩体
    （到位后按掩体建议姿态与朝向自行驻守）；分不到掩体的单位沿阵型线排开。
  - 拖动中会显示白色半透明幽灵模型预览各单位进掩体后的位置/朝向/姿态，另有阵型线、
    排开槽位（黄点）与载具槽位（角括号）标记；幽灵克隆失败会自动降级为纯标记。
  - 载具一律占线槽开到位，到位后按箭头方向原地转向——上位替代旧"载具朝向拖动"。
  - 拖动距离过短（<1 米）等效普通移动。
· 命令快捷键（cfg【Hotkeys】节可自定义）：Z 站起 / X 蹲下 / C 趴下 / V 停止 / B 停火切换 /
  N 就近掩体（以选中中心为准） / M 集合（各队向班长集结） / F 分散（就地散开找掩护） / G 背包窗口。
· 移动/登车路线显示：下达移动或登车命令后，每个行进单位到目标画灰色半透明虚线
  （登车线实时跟随目标载具），全员到位后自动消失。
· Ctrl+1~9 = 保存当前选择为编组；1~9 = 召回编组（死亡单位自动剔除，替换当前选择）。
· 下车 = 已选载具车组全部下车（并步行离开，不会立刻又上车）；入口改为左下角信息面板的 [下车] 按钮。
  **1.4.10：移动命令不再把车内乘员拉下车**——徒步移动只发给徒步单位，车里的人由载具移动链负责
  （点载具本身 / 阵型箭头）。修掉了「让单位上坦克后又会立刻下车」。
· 空格 = 暂停/继续世界（暂停时镜头仍可移动）。
· 右下角【小队列表】= 编号 + 符号：每辆装甲单位一个 □，每名步兵一个 ○（□ 总在 ○ 前）。
  单击选中该队，双击选中并飞过去。
· 左下角【信息面板】：焦点单位的姓名/职类、血量条、姿态、压制度；
  ◀ ▶ 按钮在选中单位间循环切换。【背包】/【货舱】按钮打开格子背包窗口（见下节）。
  右键士兵——**他的任何部位都算他本人，头盔/装备也算（1.4.4），点在他身边也算（1.4.5 容错 2.5m，
  远景点偏不再变成普通移动）**：徒步友军=走过去开双方背包、尸体=走过去开尸包（**1.4.11 起同样同时开双方背包**——尸包 + 选中单位的背包）；
  右键地上物品=最近选中的士兵拾取（联动半径内即时、超半径走过去捡）。
  选中载具时该面板另有 [下车] / [修理] 按钮（右键交互环已删除，上车改为右键直接）。
  不可移动的火力点/火炮（无驾驶链）：选中后在任意位置长按右键即可从单位自身拉出箭头并原地转向。
· 自定义光标（cfg customCursor / cursorStyle）：空心半透明圆环，靠颜色区分——白=默认、绿=友军、红=敌军、青=载具、黄=建筑、橙=火力点、浅蓝=可交互（物品与尸体）；cursorStyle = Circle（默认）/ Arrow / Cross。
· 左键也可选中非单位的可交互物（空载具、掉落物品）。
· 无选中时下指令会提示"先框选/选中"，防止误指挥全部友军。
· FPS 模式的 WASD、鼠标视角、射击和原生操作不被 RTS 接管；切回 FPS 后，已下达的 RTS 任务仍在后台执行。

【格子背包窗口（1.3.4，MC 风格）】
· 打开：信息面板 [背包]（焦点士兵）、[货舱]（焦点载具）、G 键、**右键尸体**，或**右键徒步友军**

  **1.4.9：兵一停下来就会再触发一次开窗**（不必精确落进 3m 圈，停在 5m 内即开，日志记实际距离）。
  **1.4.10：窗口标题不再和负重数字叠字**（按可用宽度自动缩字号 → 去「背包 · 」前缀 → 省略号截断）。
  **1.4.10：派兵只在「徒步」单位里挑人**——选中的兵全在载具里时不再派他走过去（那是"下车步行"），
  改为改派最近的徒步友军过去；车里坐着的兵不会再被误当走路的人。
  会合途中改变选择不会再打断这次会合（只有进 RTS / 接管单位 / 退出 RTS 才取消）。
  可同时开多个窗口；每个窗口 = 可拖动标题栏 + 负重条 + 每页 6×4 格子（可翻页）+ 右上角关闭。

  **装备类物品额外有「穿上」**（1.4.2，按物品子类判定：1.4.3 起胸挂等 gear 类也能穿）：武器=装填并持起（官方协程）、
  衣/甲/盔=官方 Lua 穿戴调用——原生交互列表对非玩家不生成装备动作，故走士兵的官方脚本通道执行。
  **1.4.12：穿戴补齐"活体实例"后再走原生，原生若没改变状态自动直写兜底**
  （`headgear_ref/headgear_Obj/uniform_ref/uniform_Obj/vest_ref/vest_Obj` + `SetHelmetObject` / `TriggerClothingObjRefresh`），
  并剪掉菜单里对非玩家静默无效的原生穿戴条目；每次穿戴在日志里留 `前[...] 后[...]` 快照便于定位。
  **菜单是模态的**（1.4.1）：开着时下面什么都不会被点到；点菜单外或 ESC 关闭。

【配置】 BepInEx\config\er2.squadcommand.cfg
· enabled：主开关。
· moveRadius：移动到达/防守半径，默认 8 米。
· packRange：背包联动半径（米），默认 3——第一个打开的背包为锚点。
· ghostPreview：阵型拖动中的白色半透明单位预览，默认开启（克隆失败自动降级为标记）。
· customCursor：RTS 内自定义光标，默认开启；cursorStyle：Circle（默认空心半透明圆）/ Arrow / Cross。
· debugLog：调试日志开关，**默认关闭（发布版保持关闭）**。开启后输出指挥/登车/标记/阵型/**背包与穿戴**诊断
  （含 `穿戴 id=… 生效级=… 前[…] 后[…]`、`原生菜单项 …`、`会合进行中 dist=…` 等），排查问题先把它打开。
· godKey：默认 F9，进入上帝视角。
· Hotkeys 节 keyStand/keyCrouch/keyProne/keyStop/keyHoldFire/keyCover/keyRally/keyScatter/keyPack：命令快捷键，全部可改键。
· UI 节 colorBase/colorHover/colorText：界面主题色（十六进制，默认深绿半透明，与底部提示条一致），
  改后即时生效（按钮底板/描边/文字/友军脚环/选中环）。

【安装】
1. 确保已安装 BepInEx（IL2CPP 版）到游戏根目录。
2. 把 ER2_BattlefieldCommander.dll 放进 游戏根目录\BepInEx\plugins\。
3. 启动游戏，日志出现 "Loading [ER2 Battlefield Commander 1.4.20]" 即成功。

【与 Advanced Combat Movement（Responsive Orders）共存】
· 已内置兼容：恢复开火走「调用 → 回读校验 → 直写 holdFire 字段」，不会被它的 Prefix 吞掉（见 1.4.15）。
· 键位不打架：它的 F（标记/跟随）、H（停火）、F1（重开任务）走原生 PlayerController.Update，
  而上帝视角内该 Update 由本 mod 跳过 → RTS 内 F = 分散（本 mod），FPS 内 F = 它的标记命令，互不干扰。
· 它在上帝视角内不响应（同上原因，输入由 RTS 独占），退出 RTS 即恢复。
· 它自带的 AI 行为（Squad Defensive Hold / Danger Memory / Artillery Evasion）会给小队下**它自己的**
  移动令，可能覆盖我们下达的命令——这类设计层面的冲突请在它的设置页里关掉对应开关。

【已知说明】
· 上帝视角进入时会解除本阵营全部小队的原生任务拉取；接管时会自动关闭原生"选择队友"残留面板，避免提示/背景反复弹出。
· 上帝视角下已 patch Cursor 锁定（原生无法锁/隐藏光标），并禁用会抢相机的原生控制器——右键不再闪烁/重置中央。
· 完整原生小队优先使用游戏自身的 Squad 移动指令；部分选择或跨小队选择使用逐兵指令，并开启游戏的自定义指挥/移动通道。
· 登车完成判定、车辆同步重试和持久集火在退出 RTS 后继续运行；登车为全原生
  任务（下令即发出登车令，走位/入座全部原生），Mod 只做完成判定与超时补发；接管某个单位时
  只停止该单位自己的 Mod 持久任务。
· 阵型掩体指令使用游戏原生掩体系统（CoverManager / 逐兵 findCover）：原版掩体点与内容型掩体道具
  （如 Combat Cover）都直接生效，无需兼容层。
